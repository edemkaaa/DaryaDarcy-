# Фронтенд Daryadarcy

Основной веб-клиент использует Next.js 16, React и TypeScript. [Сохранённый Expo-клиент](../legacy-expo/) служит эталоном перенесённых сценариев, текстов и дизайна; [legacy-web](../legacy-web/) — более ранний Vite-клиент. Клиент работает с отдельным Express + tRPC API. Expo находится вне workspace. Команды сборки Next.js не собирают приложения iOS/Android.

## Где менять

- [src/app/](src/app/) — маршруты App Router и layout.
- [src/features/](src/features/) — экраны и сценарии разделов.
- [src/domain/](src/domain/) — сессия, подписка, профиль и обработка контента.
- [src/shared/](src/shared/) — API, навигация, браузерные функции и общие компоненты.
- [public/](public/) — изображения, шрифты, манифест и юридические страницы.
- [e2e/](e2e/) — браузерные приёмочные тесты.
- [next.config.mjs](next.config.mjs) — конфигурация Next.js и прокси API.

Общие контракты находятся в [packages/shared](../../packages/shared/). Типы tRPC в [src/shared/api/contract.ts](src/shared/api/contract.ts) генерируются из API. После изменения серверного контракта используйте `pnpm api:contract`, затем `pnpm check:api`. Клиент не импортирует серверный runtime или код БД. При изменении API согласовывайте контракт и обновляйте тестовые ответы. Текущий объём работ, результаты проверок и незавершённые задачи — в [WORK_PLAN.md](WORK_PLAN.md).

## Локальный запуск

Используйте Node.js 22 и pnpm 9.12.0, указанный в корневом `package.json`. Из корня репозитория:

```sh
pnpm install --frozen-lockfile
test -f apps/frontend/.env || cp apps/frontend/.env.example apps/frontend/.env
pnpm dev:frontend
```

Фронтенд: http://127.0.0.1:8081. В `.env` пустой `NEXT_PUBLIC_API_BASE_URL` оставляет запросы на том же origin; `API_PROXY_TARGET=http://127.0.0.1:3000` направляет `/api` и `/media` на локальный сервер. Запросы остаются на том же браузерном origin; HttpOnly cookie не требуют ослабления CORS. Next.js также читает `.env.local`; существующий `.env` можно сохранить. `EXPO_PUBLIC_API_BASE_URL` новый клиент не читает. `API_PROXY_TARGET` должен быть настроен и при сборке, и при запуске. После изменения переменных перезапустите Next.js. Не помещайте секреты в `NEXT_PUBLIC_*`.

Сам Next.js запускается без бэкенда, но данные и авторизация требуют доступного API. Браузерные регрессии ниже используют тестовые ответы и позволяют проверять фронтенд без сервера и базы. Запуск и переработка бэкенда не входят в текущую работу над фронтендом; общий `pnpm dev` запускает оба процесса; `pnpm dev:server` запускает только API на 3000. Подготовка локального API описана в [инструкции запуска](../../docs/development/getting-started.md).

Для разработки с удалённым API можно задать в локальном, игнорируемом Git файле `.env.local`:

```dotenv
NEXT_PUBLIC_API_BASE_URL=
API_PROXY_TARGET=https://daryadarcy.dev.reeskeen.ru
```

После изменения цели перезапустите `pnpm dev:frontend`. Браузер обращается к локальным `/api/*` и `/media/*`, Next.js пересылает их удалённому серверу. [src/proxy.ts](src/proxy.ts) только в режиме `development` с HTTPS-целью заменяет Origin собственного локального фронтенда на origin цели. Запросы с чужим Origin, `cross-site` или публичным Host отклоняются. Cookies передаются как обычно; вход нужно выполнить отдельно на локальном фронтенде. Production и локальный HTTP-бэкенд сохраняют прежнюю обработку Origin.

## Сборка и проверки

Команды из корня:

```sh
pnpm --filter @daryadarcy/frontend typecheck
pnpm lint
pnpm verify
pnpm build:frontend  # pnpm build:web — тот же Next.js build, результат в apps/frontend/.next
pnpm start:frontend
```

Для браузерных проверок сначала соберите фронтенд и установите Chromium для Playwright:

```sh
pnpm --filter @daryadarcy/frontend exec playwright install chromium
pnpm build:frontend
pnpm test:frontend
```

Playwright запускает production-сервер на 8081, если порт свободен. При уже запущенном сервере используется он; для проверки именно новой сборки предварительно остановите прежний процесс. Можно выбрать установленный Chromium через `PLAYWRIGHT_EXECUTABLE_PATH`.

Не запускайте `next build` в той же рабочей копии одновременно с `next dev`: оба процесса используют `.next`. Если dev-сервер нужен для просмотра во время production-проверок, собирайте отдельную копию проекта и запускайте её на другом порту. Режим разработки с HMR не подходит для проверки production-заголовков кеша.

Проверки настоящего API выключены по умолчанию. `RUN_REAL_API_TESTS=1` включает отдельные интеграционные сценарии, включая запись черновика, и требует специально подготовленного тестового API. Успешные тесты с подставными ответами не подтверждают серверные права доступа, реальные платежи или работу на всех устройствах.

## Общая навигация

[TabShell](src/app/tab-shell.tsx) оборачивает все страницы внутри корневых providers. Хедер с главной, возвратом и профилем и нижнее меню находятся вне прокручиваемого контента; загрузка, ошибка и статус подписки не скрывают их. Страницы разделов не добавляют собственные копии хедера. Музыка клуба остаётся в общем хедере.

Хедер расположен поверх страницы без отдельной фоновой полосы. На главной, в Ленте, Клубе, Библиотеке и Магазине он вписан в исходный баннер и не добавляет высоту. На остальных страницах `--screen-safe-top` сохраняет компактный отступ внутри `ScreenContainer`, поэтому текстура страницы продолжается под иконками. Сохранены исходные значки, цвета и варианты главной/магазина; пустая область хедера пропускает действия к содержимому.

[Возврат](src/shared/navigation/router.tsx) использует только историю, созданную приложением. При прямом входе кнопка ведёт в родительский раздел (пост → Лента, видео → Видео, статья → Библиотека, товар → Магазин, тест → Интерактив), либо на главную. Маркер истории сохраняет служебные поля Next.js и переживает обновление текущей вкладки. Проверки прокрутки, прямых ссылок и отказов API: [navigation-layout.spec.ts](e2e/navigation-layout.spec.ts).

## Кеш и возврат на страницу

Один [QueryClient](src/shared/api/query-client.ts) обслуживает все маршруты. По умолчанию данные считаются свежими 30 секунд, неактивный кеш удаляется через 5 минут. Это кеш в памяти текущей вкладки; после полной перезагрузки страницы он создаётся заново. Возврат фокуса и соединения не обновляет обычный контент. Открытие экрана с устаревшими данными, явная кнопка повтора и инвалидирование после изменения данных могут запускать запрос. Уведомления сохраняют свой опрос раз в 90 секунд.

[Сессия](src/domain/session/session-context.tsx) проверяется при запуске, возврате видимой страницы, восстановлении сети, изменениях сессии в другой вкладке и ошибках доступа. Парные `focus`/`visibilitychange` объединяются в пределах одной секунды; сетевое восстановление, межвкладочные события и ошибки доступа проходят сразу. [Подписка](src/domain/subscription/subscription-context.tsx) отдельно перепроверяет права при возврате видимости и сети. Фоновая проверка и временный сбой не заменяют подтверждённый экран загрузкой. Выход, смена пользователя/роли и подтверждённая потеря доступа очищают приватный кеш. Ответы API используют HTTP `no-store`, cookie отправляются через `credentials: include`: кеш данных приложения не служит подтверждением авторизации.

| Ресурс | Политика |
| --- | --- |
| Статические импорты изображений `/_next/static/media/*` | Имя с хешем; production-сервер отдаёт годовой `immutable` кеш |
| Адаптивные варианты `/assets/responsive/*` | Имя с хешем содержимого; годовой `immutable` кеш из `next.config.mjs` |
| Шрифты и прочие файлы `public` без версии в имени | Проверка актуальности (`max-age=0`); неизменённый файл может вернуть 304 по ETag |
| Фото/аватары и другие URL из API | Заголовки задаёт сервер или внешнее хранилище; годовой кеш автоматически к ним не применяется |

В текущем серверном `s3Put` нет явного `CacheControl` для новых загрузок. Поэтому проверка локальных иллюстраций не подтверждает срок кеширования загруженных пользователями файлов. Настройку таких объектов следует согласовывать отдельно с сервером и правилами доступа.

Регрессии: [контроллер сессии](../../tests/frontend-session-controller.test.ts), [кеш запросов](../../tests/frontend-query-cache.test.ts), [фокус и меню](e2e/focus-and-menu.spec.ts), [кеш браузера и возврат](e2e/cache-and-resume.spec.ts), [изоляция пользователей](e2e/session-safety.spec.ts). Проверка HTTP-кеша изображений запускается без `page.route`, поскольку [маршрутизация Playwright отключает кеш браузера](https://playwright.dev/docs/api/class-page#page-route).

Серверная оговорка из аудита: текущий `/api/auth/me` может вернуть `user: null` при внутреннем сбое проверки пользователя. Клиент обязан трактовать такой ответ как выход. Различение этого случая и настоящего отзыва сессии требует серверного исправления; бэкенд в этой работе не меняется.

## Ограничения выпуска

Прежний статический `web-dist` и старый `deploy:web` не подходят для Next.js: защитная проверка останавливает этот деплой. Запуск процесса Next.js за nginx, маршруты `/api` и `/media`, переменные сборки/запуска и rollback ещё требуют отдельной проверки и согласования. Локальная сборка не является разрешением production-релиза.
