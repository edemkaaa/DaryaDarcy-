# Бэкенд Daryadarcy

NestJS + tRPC с Express-адаптером, TypeScript, Drizzle / MySQL. Основная работа — в src; схема и миграции — в [packages/database](../../packages/database/). Это постепенный перенос существующего сервера, а не параллельная переписанная система. HTTP-сервер уже запускается через NestJS; остальные доменные адаптеры переводятся по [плану](../../tasks/plan.md). Решение и ограничения — в [ADR 0005](../../docs/decisions/0005-nestjs-modular-backend.md).

## Навигация

Где размещать новый сценарий и как согласовывать API с фронтендером — в
[регламенте команды](../../docs/development/team-workflow.md#как-раскладывать-код-внутри-приложений).

Для первого прохода используйте [маршрут чтения кода](../../docs/development/code-reading-guide.md)
и [справочник backend-файлов с блоками](../../docs/development/file-guide/backend.md).
Комментарии описывают назначение и инварианты; они не подтверждают включение
функций на сервере. Текущие локальные результаты и остаток — в
[аудите от 11 ноября](../../docs/audits/project-senior-review-2026-11-11.md).

```text
src/
  app.module.ts   композиция Nest-модулей
  _core/          запуск NestJS, TrpcModule/TrpcService, контекст и общие middleware
  system/         Nest-контроллер состояния сервера
  routers.ts      только сборка tRPC-роутеров
  identity/       Nest-модуль, контроллеры и сервисы сессий, регистрации, пароля и писем
  billing/        checkout, обработка платежей и отмена подписки
  content/        ContentModule, чтение/запись/комментарии/загрузки; лента, статьи и видео
  club/           материалы и обсуждения клуба
  profile/        ProfileModule/ProfileService: правки профиля, аватар, запрос удаления
  moderation/     ModerationModule/ModerationService: жалобы и модерация
  notifications/  push-токены и согласия
  admin/          административные процедуры
  launch/         Nest-модуль, контроллер и сервис настроек запуска; capabilities
  pen-pals/       анкеты и совпадения
  shop/           ShopModule/ShopService: покупки и checkout; запуск оплаты отключён
  workers/        WorkersModule/WorkerJobs: сборка задач без автозапуска (M07b1)
```

## Что важно при изменениях

- `routers.ts` собирает API из предметных сервисов; сценарии размещаются в
  соответствующих модулях. Совместимый `db.ts` ещё используется и не означает
  завершённый перенос слоя данных.
- Nest-зависимости конструкторов указываются через `@Inject`: сборка esbuild
  не генерирует runtime metadata типов автоматически. Импорт композиции сам
  не должен открывать HTTP listener или запускать фоновые задачи.
- Actor берётся из свежей сессии. Внутренние session-поля не включаются в
  публичный DTO; временная ошибка проверки личности не превращается в гостя.
  Браузерный JWT выдаётся в HttpOnly-cookie, без дублирования в JSON.
- REST-регистрация возвращает нейтральный `202` для существующего и нового
  корректного email. Это не вход и не обещание доставки письма. Проверку
  существования аккаунта и правила повторной отправки не раскрывать через
  отдельный публичный `409`.
- Записи редакторов используют текущие права, ревизию и исходный ключ операции.
  При потере ответа сначала выясняется результат; новый ключ означает новую
  операцию. Лайк/сохранение в форме toggle не допускают слепого повтора.
- Закрытые вложения используют `admin.uploadPrivateAttachment`,
  `admin.uploadPrivateContentFile` и соответствующие status-процедуры.
  Фото комментариев имеют отдельный приватный контракт. Возможность загрузки
  зависит от серверных флагов; точные лимиты описаны в
  [контрактах файлов](../../docs/specifications/SPEC-private-files.md).
- Старые неоднозначные публичные media/raw-video загрузки отклоняются.
  `admin.uploadPhoto` допускает только явное `purpose="publicCover"`;
  восстановление публичной обложки после потери ответа использует
  `admin.uploadPublicCover` / `admin.publicCoverUploadStatus`.
- `admin.importVideoUrl` сохраняет допустимую ссылку собственного storage,
  не скачивает и не копирует объект. Этот ответ не подтверждает существование,
  формат или размер файла. VK iframe обрабатывается отдельным контрактом.
- Возврат браузера от Prodamus не подтверждает оплату и не создаёт сессию.
  Доступ связан с проверенным settlement. `pending` отмены подписки означает
  сохранённый запрос, а не подтверждённое отключение автосписания.
- SQL-транзакция не включает SMTP, push или S3. Lease/receipt сохраняют состояние
  обработки, но не дают гарантии однократного внешнего эффекта после аварии.
  Сессии, роли и состояния, использованные для записи, проверяются на её границе.
- Для нескольких API нужны общая координация, согласованный бюджет MySQL и
  проверенная остановка workers. Тесты используют только отдельную одноразовую БД.
