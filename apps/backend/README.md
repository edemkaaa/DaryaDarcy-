# Бэкенд Daryadarcy

NestJS + tRPC с Express-адаптером, TypeScript, Drizzle / MySQL. Основная работа — в src; схема и миграции — в [packages/database](../../packages/database/). Это постепенный перенос существующего сервера, а не параллельная переписанная система. HTTP-сервер уже запускается через NestJS; остальные доменные адаптеры переводятся по [плану](../../tasks/plan.md). Решение и ограничения — в [ADR 0005](../../docs/decisions/0005-nestjs-modular-backend.md).

## Навигация

```text
src/
  app.module.ts   композиция Nest-модулей
  _core/          запуск NestJS, контекст, сессии и общие middleware
  system/         Nest-контроллер состояния сервера
  routers.ts      только сборка tRPC-роутеров
  identity/       Nest-модуль, контроллеры и сервисы сессий, регистрации, пароля и писем
  billing/        checkout, обработка платежей и отмена подписки
  content/        лента, статьи, видео, комментарии, редактирование и публикация постов
  club/           материалы и обсуждения клуба
  profile/        профиль и дополнительные поля
  moderation/     жалобы и модерация
  notifications/  push-токены и согласия
  admin/          административные процедуры
  launch/         Nest-модуль, контроллер и сервис настроек запуска; capabilities
  pen-pals/       анкеты и совпадения
  shop/           старые процедуры магазина, запуск отключён
```

## Что важно при изменениях

- routers.ts остаётся точкой сборки; проверки доступа и поведение находятся в доменных модулях.
- app.module.ts собирает Nest-модули. Используйте явный @Inject для зависимостей конструкторов: esbuild не генерирует metadata типов. LaunchService использует существующие функции Drizzle с транзакциями; общий lifecycle пула пока не переносился.
- IdentityModule экспортирует SessionService и HTTP-guards для настроек/повторных писем. Guards проверяют свежую сессию и роль, контроллер получает пользователя от guard, не из тела запроса. Это не замена транзакционной проверки прав и не глобальный guard для всех маршрутов; tRPC пока использует прежний контекст.
- Клиент получает тип AppRouter; не копируйте серверные функции в фронтенд.
- Регистрация подтверждается письмом: ответ 202 не означает вход или выданную сессию.
- Checkout не авторизует по email, claim не выдаёт доступ. Платежи и письма имеют сохранённое состояние обработки.
- Пароль устанавливается одноразовой ссылкой; смена пароля изменяет версию сессий.
- Проверяйте повторные запросы, конкуренцию, истёкшие ссылки, заблокированные аккаунты и ошибки внешних сервисов.
- Изменение API должно сопровождаться тестами; [снимок контракта](../../__tests__/trpc-contract.test.ts) защищает имена процедур.

Актуальные ограничения выпуска — в [tasks/todo.md](../../tasks/todo.md).
