# Public-video worker

Отдельный сервис для опубликованных YouTube-роликов тестового стенда. Не получает
доступ к базе, SMTP, пользовательским cookies или файлам основного API. Каталог
читает через существующий публичный `videos.list` на внутреннем edge.

## Проверка и сборка

Из корня проекта, Node 22:

```sh
pnpm test:video
pnpm exec vitest run tests/video-service.test.ts
docker build --platform linux/amd64 -t daryadarcy-video:<version> apps/video-service
```

Новых npm-зависимостей нет. HTTP, кеш и процессы используют стандартную библиотеку
Node; native-тесты также запускаются общим `pnpm test` через Vitest-обёртку.
В контейнере установлены FFmpeg из подписанного репозитория Debian и официальный
yt-dlp 2026.08.19, проверяемый по фиксированному SHA-256. Runtime закреплён digest.
Не используйте обновление загрузчика при запуске или сторонние плагины/cookies.

## Поведение

- `GET/HEAD /api/yt/<youtubeId>`: MP4 H.264 + AAC, максимум 720p, поддержка одного
  byte range (включая suffix). Неизвестный/неопубликованный ID — 404; недоступный
  каталог/источник — 502; занятый сервис — 503, некорректный range — 416.
- `GET/HEAD /media/yt-thumb/<youtubeId>/hqdefault.jpg`: проверенная JPEG-обложка
  опубликованного ролика. Никаких переданных клиентом URL.
- `/health`: состояние процесса, без обращения к интернету или базе. Это не
  подтверждение доступности YouTube или конкретного ролика.
- Публикация проверяется заново на каждом запросе и после подготовки. Нет
  долгоживущего разрешающего списка и выдачи кеша в обход текущего каталога.
- Первый запрос скачивает выбранные видео/аудиодорожки и объединяет их **без
  перекодирования**. Файл подготовлен для начала проигрывания/перемотки через
  `faststart`; первый запуск требует ожидания полного скачивания.

## Ограничения

Одна подготовка одновременно; одинаковые запросы объединяются, другая новая
подготовка получает 503. До 16 активных HTTP-запросов, подготовка до 150 секунд,
запрос до 170 секунд. Последний ушедший зритель отменяет ненужную подготовку;
отмена одного зрителя не обрывает загрузку оставшимся.

Кеш полностью временный: filesystem `/cache` ограничен **384 МиБ**, готовые
файлы — **128 МиБ** суммарно, остаток зарезервирован под промежуточные дорожки и
объединение. Готовый файл до 112 МиБ, ролик до 45 минут; срок хранения 30 минут.
Активный файл не вытесняется. `/tmp` до 96 МиБ отдельно нужен упакованному
загрузчику. Весь контейнер: до 640 МиБ, 0.75 CPU, 128 процессов, без root,
привилегий и опубликованного порта. Рестарт очищает кеш.

Это тестовое решение, не гарантия стабильности YouTube и не промышленный CDN.
Недоступные/слишком большие/длинные/другие кодеки не обходятся аккаунтом или
отключением ограничений. Приватные и платные материалы этим сервисом не выдаются.
Публичный каталог ограничен 1000 записями/2 МиБ ответа: превышение — отказ, не
частичный разрешающий список. Для большого каталога нужен отдельный точечный
публичный read-контракт, а не доступ worker к рабочей базе.

Развёртывание, сохранение действующей SMTP-конфигурации и откат описаны в
[руководстве стенда](../../docs/operations/teamassist-staging.md).
