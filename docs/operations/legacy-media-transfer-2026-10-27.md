## Почему поток, а не CopyObject

На собственных маленьких объектах Timeweb фактически вернул **200** для
CopyObject с `IfNoneMatch="*"` при существующем назначении: защита от перезаписи
не сработала. Условие источника вернуло 412, но это не защищает назначение.
Обычный PutObject с тем же условием назначения вернул **412**. Поэтому
экспериментальный CopyObject не используется в реализации переноса.

Путь `s3Stream` выполняется отдельным операторским процессом, последовательно
по одному файлу. Это не HTTP-загрузка редактора и не новая публичная процедура.

1. Проверить настроенный namespace, защитную policy, размер и ETag источника.
2. Проверить назначение. Чужой объект или несовпадающие metadata — остановка.
3. Прочитать источник потоком с IfMatch, вычислить полный SHA-256/MD5,
   проверить сигнатуру. При заданном исходном SHA он обязан совпасть.
4. Ещё раз открыть тот же ETag и передать поток в PutObject: точный
   ContentLength, ContentMD5, `IfNoneMatch="*"`, private ACL, no-store.
   Поток дополнительно проверяет размер и SHA до своего завершения.
5. Проверить metadata, ETag и полный SHA назначения. Только после этого возможна
   готовность receipt и отдельная атомарная привязка.

Видео не перекодируется, не записывается на диск и не собирается целиком в RAM.
Буферы потока ограничены; проба — до 64 КиБ. Цена проверки целостности — три
полных чтения (два источника, одно назначения) и одна запись по сети.
Соединение ограничено 5 секундами, socket/idle — 30, операция — 300 секундами.
Зависшая или слишком медленная передача останавливается, привязка не меняется.
Реальные большие файлы и пропускная способность этим шагом не приняты.

## Контракт оператора и откат

[Manifest](../../apps/backend/src/content/legacy-media-manifest.ts) принимает
version=1, idempotencyKey, operationId=SHA-256(JSON([subject,expectedOldUrl])),
точный subject (postPhoto/articleMedia/postMedia, id, slot), expectedOldUrl,
preserveOriginal=true, filename, type, expectedSourceBytes.

Для фото/документа — проверенные `bytes` и обязательный expectedSourceSha256.
Для видео — transport=s3Stream, expectedSourceETag, probe и
expectedSourceSha256 (null допустим до первого полного чтения).
Адрес источника — только разрешённые старые ключи собственного S3, без query,
fragment, traversal и private-v1. Произвольные пути диска/URL не скачиваются.

[applyLegacyMedia/rollbackLegacyMedia](../../apps/backend/src/content/legacy-media-migration.ts)
вызываются операторским процессом с действующим actor id/sessionVersion.
Не подключать этот импорт к REST/tRPC или фронтенду. Рабочий DATABASE_URL и
секреты передаются процессу из закрытого окружения, не через аргументы/лог.
Локальный пакет хранится вне Git: каталог 700, файлы 600. Перед вызовом проверить
обычный файл без symlink, имя/размер/хеш; последовательность взять из закрытого
manifest, не из обхода папки по маске.

Используются существующие receipt-таблицы и 44 миграции; новых DDL нет.
Intent фиксируется до внешней записи. Сеть работает без SQL-блокировок.
Перед фиксацией повторно проверяются роль, sessionVersion, флаги, receipt и
точная прежняя ссылка. Меняется один выбранный слот; ID вложения, порядок,
остальные блоки, обложки и даты публикаций сохраняются. События/письма не шлются.

Потеря ответа восстанавливается по тому же ключу и metadata; другой payload
или namespace с тем же ключом отклоняется. Прерывание после записи оставляет
непривязанный закрытый объект для восстановления; автоматического DELETE нет.
Отменённую операцию поздний ответ не возобновит.

Откат восстанавливает старую ссылку только при совпадении ожидаемой новой и
не перетирает последующее редактирование. Receipt выводится из обращения,
источники/копии не удаляются. После закрытия старого публичного адреса такой
откат ссылки сам по себе не восстанавливает выдачу: нужен согласованный
закрытый путь восстановления; автоматически открывать старый источник нельзя.

## Доказательства и ограничения

- Локальный storage wire: совпадение байтов/SHA, много сетевых чанков, запрет
  чужого назначения, неправильного SHA/сигнатуры/policy/namespace/размера,
  восстановление после потери ответа без второго PUT.
- Одноразовая fresh44 MySQL + настоящий локальный API: фото/GIF/документы/видео,
  Range, admin/member/guest/no-access/revoke, атомарность при SQL-отказе,
  смена роли во время передачи, конфликт редактирования и guarded rollback.
  Отдельные процессы проверяют потерю уже зафиксированного ответа и повтор.
- Настоящий Timeweb + одноразовая БД: собственный синтетический объект 28 байт,
  потоковый PUT/повтор, SHA, API-доступ/отзыв, анонимный прямой URL 403,
  отказ перезаписи 412, откат. Это проверка протокола, не воспроизведения видео.
  Два созданных тестовых ключа удалены только после проверки принадлежности;
  последующий HEAD подтвердил 404. Версионирование/исходная policy не менялись.
- Все **388 подготовленных входов** прошли production-валидатор: 0 ошибок.
  Фото/документ проверены целиком, видео пока по ограниченной пробе/ETag.
  Нельзя объявлять этот пакет выполненным переносом или готовыми привязками.

Финальный прогон: **3 396 passed / 1 755 skipped**; отдельно **42 focused**,
**20 native SQL/API** и **1 real Timeweb canary** прошли. Пропуски общего
прогона — отдельные SQL/image/external suites без их окружения; результат не
означает их приёмку. Types (root/frontend/E2E), API102, boundaries805,
backend+TEST builds и проверка ссылок документации прошли. Production audit:
0 известных уязвимостей. Новых зависимостей нет. Одноразовая БД удалена по
exact ID/name/owner/tmpfs guard; OOM=false/restarts=0, volumes не создавались.
Ревью: границы URL/прав/receipt, отсутствие сети внутри SQL-lock, отмена/повтор,
условная запись и проверка полного потока, отсутствие frontend/DDL/рабочих write.

Закрытые receipts/логи находятся вне Git в `.local-artifacts/legacy-migration-20261027`:
stream-pack-validation.json, stream-native-process.log, stream-focused-final.log,
timeweb-canary.log и provider-capabilities.json (в том числе отрицательный
результат CopyObject). Там же исходные manifest/пакет и read-only доказательства.
Публичные документы не содержат старые платные URL, ключи и персональные данные.
