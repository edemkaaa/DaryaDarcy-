## Инцидент финальной сверки

При первой финальной сверке два проверочных mysql-клиента были запущены
параллельно внутри контейнера БД. Его лимит 512 МиБ оказался исчерпан;
журнал ядра подтвердил cgroup OOM и завершение mysqld. Контейнер автоматически
перезапустился один раз, InnoDB завершил восстановление. API/TEST не перезапускались
и не были OOM-killed. Это сбой процедуры проверки, он не скрыт общим итогом GREEN.

Сверка перенесена в последовательный отдельный процесс с лимитом 96 МиБ,
использующий обычного SQL-пользователя приложения и read-only SQL-сессию.
Дополнительные клиенты больше не запускаются внутри контейнера MySQL;
лимиты и конфигурация приложения не менялись. После этого полная сверка
прежних данных и администраторов совпала, обе истории проверены повторно,
API и публичный HTTPS прошли повторные проверки. Восстановление рабочей БД
не потребовалось. Остальные приложения сохранили контейнеры и время запуска;
у MySQL отдельно зафиксирован этот перезапуск.

Перед нагрузочным пилотом нужно отдельно пересмотреть запас памяти MySQL.
Этот выпуск не подтверждает вместимость текущего сервера для 100 одновременных
пользователей. Увеличение лимитов в рамках этого поручения не выполнялось.
