## После разрешения на настройку

Владелец разрешил настройку CI/CD и runner, без рабочей машины и выкладки.
Попытка через API не изменила настройки: существующий токен имеет `read_api`,

Это отдельное ограничение изменения настроек, в дополнение к выключенному CI/CD
ниже. В браузере открыта страница входа; ожидается пользовательская сессия.
Доступных runners не найдено, отдельная машина пока не предоставлена.

Подготовлен [пакет отдельного runner](../../infrastructure/ci/gitlab-runner/README.md).

manifest manager19.5.0 проверен без pull. Runner не создан/не установлен,
pipeline не запускался, новый пакет ещё не опубликован. Рабочие ресурсы прежние.

**Результат:** CI/CD выключен, доступных проекту runners не обнаружено.
Удалённые проверки staging не приняты. Наличие `.gitlab-ci.yml` и успешные
локальные проверки не означают, что GitLab выполнил этот pipeline.

## Что нужно DevOps

1. По отдельному решению владельца включить CI/CD в настройках проекта.
   Запрет на новую выкладку сохраняется: текущий pipeline содержит проверки,
   а запуск или добавление deployment jobs в этот шаг не входит.
2. Подключить подходящий runner: проектный либо разрешённый групповой/общий.
   Текущие jobs не задают tags, поэтому runner должен принимать такие задания.
   Executor должен поддерживать контейнеры и MySQL service для `verify`;
   shell runner без соответствующей изоляции не считать эквивалентом.
3. Использовать отдельные ресурсы runner, не действующий сервер приложения.
   Для проверок не нужны production DATABASE_URL, SMTP, S3 или Prodamus.
   MySQL service в YAML содержит только одноразовые тестовые реквизиты.
4. После разрешения на запуск проверить нужный полный SHA staging. Сохранить
   ссылку на pipeline, SHA, статусы всех jobs и browser JSON artifacts.
   Нужны `verify` и обе matrix-ветки `checkout-browser`.
5. Общий browser-набор содержит известные задания фронтендеру по fixtures.
   Не скрывать их через `allow_failure`, исключение tests или выдачу skipped
   за pass. Исправления перечислены в
   [едином документе фронтендеру](../development/frontend-request-audit-actions-2026-10-30.md).

Профили и критерии: [checkout browser CI](checkout-browser-ci-2026-10-30.md).
Полная native сборка образов — отдельный gate
[пакета DevOps](../../infrastructure/build/README.md),
а не побочный эффект включения CI/CD.
