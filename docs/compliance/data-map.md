## Техническое уточнение по коду, 11 ноября 2026

Разделы A–E ниже сохраняют исходный материал августа. Их перечень таблиц,
провайдеров, инфраструктуры и отметки «не внедрено» устарели; их нельзя копировать
в уведомление как проверенное текущее состояние.

| Область | Что следует из текущего кода |
| --- | --- |
| Пользователь | `users` содержит email, хеш пароля, роль, ревизии, прежний `phone` и отдельный `contactPhone`. Контактный номер сообщается без SMS, не служит способом входа и не перезаписывает уже заполненный контакт после оплаты |
| Подписка и операции оплаты | Заказы, подтверждения, долговечные намерения и журналы повторов описаны в [карте БД](../architecture/database.md). Возврат браузера не является оплатой |
| Письма | Outbox и одноразовые proof имеют собственный жизненный цикл. SMTP-принятие, доставка в ящик и прочтение — разные результаты; конкретный провайдер определяется закрытой конфигурацией |
| Контент и взаимодействия | Посты, комментарии/фото, реакции, статьи и привязки файлов имеют серверные проверки доступа; публичный URL аватара/обложки не равен праву на закрытое вложение |
| Квиз | У браузерного клиента есть журналы прохождения/результата и серверный сценарий профиля. Утверждение ниже «только AsyncStorage» относится к прежнему Expo-клиенту |
| Pen Pals | Заявки и адреса присутствуют в модели, но их доступность определяется feature policy. Наличие таблиц не разрешает включение функции |
| Удаление и аудит | Есть запрос удаления аккаунта, журнал административных действий и maintenance-код. Реальные сроки/включённые worker и организационный процесс проверяются отдельно |
| Push и видео | Основной клиент — Next.js; Expo архивный, Web Push не подключён. Текущий видеокаталог использует VK. Старые схемы Expo/YouTube ниже — история |
| Хранение и логи | Код не подтверждает страну новой БД, расположение резервных копий, доступность прежнего сервера, настройки DNS/TLS или сроки логов. Эти сведения подтверждают оператор и DevOps по фактическому развёртыванию |

Полный состав модели: [database.md](../architecture/database.md). Границы внешних
передач: [integrations.md](../architecture/integrations.md). Изменения технического
описания не заменяют согласование целей, оснований, сроков хранения и получателей
с оператором данных.

## A. Какие данные собираем и где храним (общая карта)

### A.1. Данные пользователей (персональные)

| Категория | Поля | Где хранится | Срок |
|-----------|------|--------------|------|
| Регистрация / профиль | имя, email, телефон, пол, URL аватара, хеш пароля | MySQL `users` (Timeweb) | до удаления аккаунта |
| Авторизация SMS | телефон, хеш OTP-кода, IP, TTL 5 мин | MySQL `sms_codes` | кратковременно, до использования/истечения |
| Подписка клуба | userId, orderId, email, сумма, статус, срок подписки | MySQL `club_payments`, `club_subscriptions` | период подписки + 30 дней (политика) |
| Покупки в магазине | userId, orderId, email, productId, сумма | MySQL `shop_purchases` | по политике / до удаления аккаунта |
| Pen Pals (по желанию) | интересы, город, **почтовый адрес** | MySQL `pen_pal_profiles` | до отзыва анкеты / удаления аккаунта |
| Комментарии клуба | userId, текст | MySQL `post_comments` | до удаления |
| Лайки / сохранения | userId, postId | MySQL `likes`, `saved_posts` | до удаления аккаунта |
| Push (native) | Expo push token, platform, userId | MySQL `push_tokens` | до logout/удаления токена/аккаунта |
| Согласие на рекламные push | userId, тип, статус, версия текста, platform, дата | MySQL `push_consent_events` | журнал (хранится для доказательства согласия) |

**Не храним:** номера банковских карт (обрабатывает Prodamus), дату рождения, отдельный псевдоним.

**Не на сервере:** результат квиза — только локально на устройстве (AsyncStorage).

### A.2. Технические / не персональные

- Посты, видео, статьи, медиафайлы — MySQL + Timeweb S3 (`s3.twcstorage.ru`, bucket `daryadarcy-s3`).
- Логи PM2 на VPS — IP, URL запросов, ошибки (без целенаправленного хранения ПДн; **уточнить срок ротации логов на VPS**).

### 4. Данные, передаваемые в Expo Push, APNs, FCM

**Цепочка (только native iOS/Android, только при наличии push-токена):**

```
Backend (Timeweb VPS, РФ)
  → Expo Push API (exp.host, США)
    → iOS: Apple APNS (США)
    → Android: Google FCM (США / глобально)
```

**Что передаётся:**

| Данные | Передаётся | Примечание |
|--------|------------|------------|
| Expo Push Token (`ExponentPushToken[…]`) | Да | идентификатор устройства, не ФИО |
| Заголовок и текст уведомления | Да | только превью поста, **без** ФИО, адресов, платёжных данных |
| userId, email, телефон | **Нет** | не включаются в payload push |
| postId, type | Да | технические поля для открытия поста в приложении |

**Рекламные push** (новые посты, акции и т.п.) — **только** при отдельном согласии пользователя (`push_consent_events`, marketing, granted). Разрешение ОС ≠ согласие на рекламу.

**Сервисные push** (подписка, оплата) — отдельный тип, без marketing opt-in (функционал готовится / сервисные сообщения минимальны).

### 8. Меры защиты, журналирование, 2FA, автоудаление

#### Реально внедрено

- HTTPS (TLS) на daryadarcy.com  
- Пароли — scrypt-хеш, не plaintext  
- SMS-коды — SHA-256, TTL 5 минут  
- JWT-сессии (cookie web / Bearer native)  
- Разделение ролей `user` / `admin`  
- Проверка подписи webhook Prodamus  
- Рекламные push — только с явного согласия + журнал `push_consent_events`  
- Удаление push-токенов при удалении аккаuntа (admin API `purgeUserPushData`)  
- Политика конфиденциальности в приложении  

#### Не внедрено (честно указать в приложении / дорожной карте)

- **Журнал admin-действий (audit log)** — нет, только PM2 logs  
- **2FA доступа к MySQL / админке** — нет  
- **Автоматическое удаление** аккаунтов по таймеру в коде — **нет**  
- Удаление по запросу пользователя — **вручную**, 14 рабочих дней (daryadarcy19@gmail.com)  
- После отмены подписки — 30 дней по политике, затем удаление (**ручной процесс**)  
- Pen pals: автоудаление 90/30 дней — **запланировано, не внедрено**
