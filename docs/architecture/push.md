# Push-уведомления

В проекте есть нативная интеграция Expo Push для iOS и Android. Для web, включая браузеры Android/iPhone, Web Push не реализован: [web-регистрация](../../apps/legacy-expo/lib/register-push.web.ts) — пустая реализация, а [серверный флаг webPush](../../apps/backend/src/launch/capabilities.ts) равен false.

## Где находится код

- [Нативная регистрация устройства](../../apps/legacy-expo/lib/register-push.ts).
- [Серверная отправка](../../apps/backend/src/push.ts).
- [tRPC: токены и согласия](../../apps/backend/src/notifications/router.ts).
- [Текст и версия согласия](../../packages/shared/src/push-consent.ts).
- [Схема push_tokens / push_consent_events](../../packages/database/src/schema.ts).

В коде различаются сервисные и маркетинговые уведомления. Для маркетинговой отправки проверяется отдельное согласие; действия с ним записываются в журнал. Разрешение ОС на уведомления и согласие внутри приложения — разные состояния.

## Что нужно проверить перед выпуском

- Регистрацию токена и доставку на физических iOS/Android.
- Включение и отзыв согласия, отсутствие отправки после отзыва.
- Отсутствие передачи закрытого контента пользователям без доступа.
- Ошибки транспорта и устаревшие токены.
- Тексты уведомлений: не включать секреты и чувствительные данные.

Существующий код не означает гарантированную или однократную доставку и не заменяет приёмку. Web Push потребует отдельной реализации и проверки браузерных ограничений.

Деплой и миграции — только по [согласованному рабочему процессу](../development/workflow.md). [Материалы по персональным данным](../compliance/) — исходные документы для профильной проверки, не готовое юридическое заключение.
