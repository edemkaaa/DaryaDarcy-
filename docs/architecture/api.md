# API и границы модулей

Описание сверено с исходниками 11 ноября 2026 года. Оно объясняет код,
а не состояние развёрнутого сервера. Датированные результаты приёмки находятся
в [аудитах](../audits/README.md), открытые работы — в [плане](../../tasks/todo.md).

## Запуск и владение зависимостями

[Точка запуска](../../apps/backend/src/_core/index.ts) загружает окружение,
собирает [Nest-приложение](../../apps/backend/src/_core/application.ts)
с Express-адаптером, открывает HTTP и запускает фоновые задачи.
Фабрика композиции сама не открывает listener и не создаёт интервалы.
[AppModule](../../apps/backend/src/app.module.ts) связывает доменные модули.
[TrpcService](../../apps/backend/src/_core/trpc.service.ts) получает сервисы
через Nest и создаёт HTTP-роутер и контекст текущего приложения.
Standalone `appRouter` сохранён для инструментов и прямых тестовых вызовов.

Порядок HTTP-границ: защита запроса, raw webhook и admission загрузок,
ограниченные парсеры, tRPC/REST-обработчики. Стандартный body parser Nest
отключён. Перестановка middleware способна изменить подписанные байты webhook
или прочитать большое тело до авторизации.

[Остановка API](../../apps/backend/src/_core/api-shutdown.ts) прекращает новые
фоновые запуски, ожидает текущую работу и закрывает приложение/пул.
Срок ожидания ограничен. Потеря worker lock приводит к аварийному завершению
затронутого процесса; его восстановление принадлежит инфраструктуре.
Подробности нескольких реплик — в [контракте координации](multi-api-coordination-2026-11-03.md).

## tRPC

Базовый путь — `/api/trpc`. Точный перечень процедур фиксирует
[тест контракта](../../tests/regression/trpc-contract.test.ts). Клиент получает
сгенерированные `ApiInputs`/`ApiOutputs`: `pnpm api:contract`, проверка
`pnpm check:api`. Форму ответов нужно менять в серверном типе/схеме,
а затем генерировать контракт; ручное дополнение клиента скрывает расхождение.

| Граница | Владелец сценария |
| --- | --- |
| `auth` | [Identity](../../apps/backend/src/identity/router.ts): сессия, профиль, выход |
| `feed`, `articles`, `videos` | [ContentReadService](../../apps/backend/src/content/content-read.service.ts): видимость, списки, карточки и каталог |
| Создание, правка, публикация, реакции | [ContentWriteService](../../apps/backend/src/content/content-write.service.ts) и транзакционные helpers `content/` |
| `club` обсуждения | [ContentCommentService](../../apps/backend/src/content/content-comment.service.ts) |
| `club` checkout/подписка | [Billing](../../apps/backend/src/billing/): создание намерения, подтверждённый доступ и отмена |
| `admin` | [Роутер](../../apps/backend/src/admin/router.ts): административная граница, журналы операций и доменные сервисы |
| `profile`, `profileExtras` | [Профиль](../../apps/backend/src/profile/profile.service.ts): поля, аватар, экспорт и запрос удаления |
| `notifications` | [Notifications](../../apps/backend/src/notifications/router.ts): серверная возможность, квота и согласия |
| `moderation` | [Модерация](../../apps/backend/src/moderation/router.ts): жалобы и блокировки |
| `penPals` | [Почтовое отделение](../../apps/backend/src/pen-pals/router.ts): анкеты, согласия и участие в паре |
| `shop` | [Shop](../../apps/backend/src/shop/shop.service.ts): сохранённый совместимый контур; онлайн-оплата выключена |

Роутер проверяет форму запроса и права. Сервис определяет последовательность
сценария. SQL-репозиторий читает данные; транзакционные helpers связывают записи.
`db.ts` сохраняет совместимые фасады и прежний ленивый клиент. Он не создаёт
отдельный пул для каждого модуля. Права нельзя считать выполненными только
потому, что helper вызван из доверенного файла.

## Сессия, роли и ошибки

[SessionService](../../apps/backend/src/identity/session.service.ts) проверяет
JWT и актуальный аккаунт: существование, блокировку и `sessionVersion`.
Роль берётся из текущей записи. Запрос удаления аккаунта не является глобальным
запретом сессии: отдельные операции повторно проверяют его перед записью.
`publicUser` явно выбирает публичные поля; SQL-модель не является DTO.
Веб-вход устанавливает HttpOnly cookie; токен сессии не нужен в JSON-ответе.
Регистрация через письмо возвращает 202 без сессии и не раскрывает отдельным
успешным ответом наличие адреса. Пароль устанавливается одноразовой ссылкой.

Подтверждённо отсутствующая/недействительная сессия допускает гостевой ответ.
Сбой БД или другого инфраструктурного этапа не является гостем:
REST-проверка сессии возвращает безопасный 503 без очистки cookie;
tRPC передаёт безопасную серверную ошибку. `5xx` не подтверждает выход.
Обработчик выхода выполняет серверный отзыв; удаление cookie само по себе
не считается достаточной защитой старого токена.

[Общая HTTP-политика](../../apps/backend/src/_core/http-security.ts) и
[границы tRPC](../../apps/backend/src/_core/trpc.ts) скрывают SQL, stack,
credentials и внутренние сообщения. Чистые типы ошибок не заменяют проверку
фактического ответа. Сбой чтения вложений не должен выглядеть успешным
постом с пустым массивом файлов.

## Чтение, страницы и публичные ID

Лента, Клуб и «Сохранённое» проверяют видимость на сервере. Наличие ID в
закладках не даёт права читать клубный текст. Карточка поста принимает старый
числовой ID либо `publicId` UUID; UUID является адресом, не правом доступа.
Внутренние связи таблиц и часть совместимых операций остаются числовыми.

Клуб сортируется хронологически до пагинации; Лента сохраняет приоритет
`sortOrder`, затем дату и ID. Старые числовые cursors
некоторых списков остаются offset; новые страницы нельзя произвольно
пересортировывать после склейки на клиенте. Каталог VK имеет отдельный
forward cursor и отдаёт разрешение воспроизведения отдельно от карточки.
Точные пределы и поля задают схемы соответствующих роутеров.

## Редакторы и неизвестный результат

### Ключ повторного создания публикации

Ключ операции принадлежит пользователю и одному неизменяемому намерению.
Создание с тем же ключом и теми же принятыми данными возвращает сохранённый
результат; другие данные дают конфликт. Новый ключ означает новую операцию.
Строки журнала и результат создаются одной транзакцией. Удаление материала
не должно позволять позднему повтору создать его заново.
См. [ADR создания](../decisions/0004-post-creation-idempotency.md),
[создание поста](../../apps/backend/src/content/post-creator.ts) и
[создание статьи](../../apps/backend/src/content/article-writes.ts).

[Ревизии](../../apps/backend/src/content/content-edit-revision.ts) сравниваются
с актуальной строкой под блокировкой. Переданный `expectedRevision` проверяется
даже при необязательном строгом режиме. Строгий режим определяется
`CONTENT_EDIT_REVISIONS_REQUIRED`; его включение требует готовности клиентов.
Конфликт не должен затирать параллельную правку или очищать ввод редактора.

Статусные процедуры отделяют восстановление результата от новой записи.
После потери ответа нельзя считать timeout доказательством rollback.
Лайк и сохранение используют toggle: слепой повтор способен отменить уже
сохранённое действие, поэтому сначала сверяют состояние.
Публикационный push отправляется после commit в согласованном best-effort
режиме. Потеря уведомления не отменяет публикацию; гарантированная очередь
для этого push не добавлена.

## Загрузки и выдача файлов

Действующие закрытые загрузки отделяют сохранение объекта от привязки к посту,
статье или комментарию. Ключи загрузок и статусные вызовы позволяют восстановить
результат. Смена аккаунта, отзыв доступа и допустимое назначение файла повторно
проверяются при привязке/выдаче. Публичная обложка имеет явное назначение
`publicCover`; её нельзя использовать как универсальную загрузку клубных файлов.

[Парсеры тела](../../apps/backend/src/_core/request-bodies.ts) выбираются по
точному маршруту и именам tRPC-процедур, включая batch. JSON media-конверт
ограничен 50 МиБ, photo — 6 МиБ, обычные процедуры — 256 КиБ, auth — 16 КиБ.
Это пределы кодированного запроса. Квоты декодированных фото/документов
проверяются отдельно. Приватное бинарное видео имеет ограничение 80 МиБ и
admission до чтения тела. Режим UTF-8 JSON использует ограниченный потоковый
путь, чтобы не создавать повторную полную сериализацию Express-объекта.

Прежние `admin.uploadMedia`, `club.uploadCommentPhoto` и
`POST /api/admin/upload-video` выведены из использования: отказ не должен
переключаться на публичную загрузку. Сохранённые записи этих процедур в типах
не подтверждают их доступность. MIME, сигнатуры, размер, имя, лимиты и
идемпотентность задаются соответствующим контрактом; расширение URL не является
доказательством формата. Проверка формата не равна антивирусной проверке.

Приватная выдача идёт через серверную авторизацию с `private, no-store`.
Библиотека имеет отдельные флаги и привязки, поэтому `/api/capabilities` с
разрешёнными загрузками не доказывает готовность её файлов. Закрытие старых
публичных копий является отдельной операцией хранилища. SQL и S3 не образуют
одну транзакцию; автоматическое удаление объектов после неопределённого commit
может сломать уже сохранённый материал и не включается без проверки ссылок.

## Оплата, возможности и границы проверки

Checkout, возврат браузера и email не подтверждают оплату или сессию.
Доступ выдаёт проверенное settlement с durable receipt. Отмена возвращает
`pending` либо `confirmed` и сохраняет оплаченный срок; pending не является
подтверждённой остановкой списаний у провайдера. Принятое SMTP-письмо не означает
доставку во входящие. Телефон связи без подтверждения не становится способом входа.

Серверные флаги действуют независимо от видимости кнопок. SMS и Pen Pals
требуют соответствующей конфигурации; Web Push и онлайн-оплата Магазина
закрыты текущей серверной политикой. Администратор тоже проходит проверки
флага, актуального аккаунта и назначения операции.

Типы, unit/SQL-тесты и сборка не заменяют приёмку реального провайдера, S3,
устройств, прокси и восстановления на целевом сервере. Подробности находятся в
[описании БД](database.md), [интеграциях](integrations.md) и
[карте исходников](../development/file-guide/backend.md).
