# Повторная проверка отзыва прав модератора

4 ноября 2026. Исследован commit `77dd4856`. Общий аудит остаётся открытым.

## Подтверждённый P1

Два маршрута допускают завершение уже авторизованного запроса после отзыва
прав сотрудника. `moderation.dismissCommentReport` удаляет жалобу,
`moderation.deleteReportedComment` удаляет чужой комментарий.

Причина находится в `apps/backend/src/moderation/user-writes.ts:18` и `:35`.
Транзакции выполняют удаление без повторной проверки actor. Router в
`apps/backend/src/moderation/router.ts:13` и `:23` передаёт только ID,
поэтому актуальную sessionVersion сравнить в этих helpers невозможно.
Удаление комментария использует внутренний cascade с asStaff=true.

На одноразовой MySQL 8.4 применены 51 штатная миграция. Контекст настоящего
appRouter сохранён при роли moderator. Затем отдельно проверены снятие роли,
блокировка с увеличением sessionVersion и увеличение только sessionVersion.
В каждом случае оба маршрута вернули ok=true, а SQL подтвердил удаление
синтетических жалобы и комментария. Получены 3 RED-теста на отказ и
9 пройденных проверок предыдущего исправления. Продолжительность 1,32 с.

Это воспроизведение ранее начатого запроса с сохранённым контекстом.
Свежий HTTP-вход после отзыва сессии этим тестом не проверялся. Рабочий стенд
в воспроизведении не использовался.

## Минимальное исправление

Передать id/sessionVersion сотрудника из router через service в SQL writer.
До удаления блокировать users-строку, сверять epoch, блокировку и актуальную
роль admin/moderator. Проверку и удаление вместе с журналом действий выполнять
в одной транзакции. Публичные параметры и ответы API сохраняются.
Новая миграция для исправления не требуется.

Регрессии должны проверять отказ и сохранность жалобы/комментария после каждого
варианта отзыва прав, а также успешную модерацию действующим сотрудником.
Прежний результат приёмки образов 40/40 этих сценариев не покрывает.
До выпуска требуется исправить новый P1 и проверить обновлённый образ.

## Проверенный срез и остаток

- Предыдущий fix в обычных club/feed mutations сохраняется — 9/9 его SQL-тестов.
- Существующие тесты модерации пользователей, жалоб, комментариев и ревизий
  профиля — 42/42 в пяти файлах за 4,63 с. Их зелёный результат не закрывает P1.
- В profile.update найдены текущие epoch/revision guards. Это чтение исходников
  и существующие профильные тесты, а не завершённый аудит всех профильных upload путей.
- Повторная проверка доступа к посту/подписке между предварительным чтением
  и записью комментария требует отдельного конкурентного теста.
- blockUser/unblockUser перечитывают текущую роль и блокировку, но передают
  только actorId. Сценарий устаревшей версии после разблокировки ещё не проверен.

Локальные доказательства сохранены рядом с репозиторием в
`../.local-artifacts/followup-review-20261104`. RED-исходник сохранён отдельно,
временный тест удалён из рабочего дерева. Оба одноразовых контейнера удалены,
тестовые данные уничтожены. Код приложения в этом исследовании не менялся.
