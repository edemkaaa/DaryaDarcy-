## Незакрытые случаи

1. **Рецепты и Петербург — нет файлов для выдачи.** Authenticated endpoints
   возвращают200 `{files:[],nextCursor:null}`. Текущий frontend всегда использует
   защищённый API, даже при старом build-time library flag=false; пустой список
   показывает «Материал сейчас недоступен». Сочетание API и исходников доказывает
   недостающие bindings; сам клик сейчас не принят. Выкройки4и guides7 готовы.
   Сохраняется прежнее указание пользователя не переносить эти два материала
   без согласования; публичные fallback/Яндекс-ссылки не включались.
2. **Оплата — только TEST.** Предыдущая read-only проверка25октября подтвердила
   отдельный Prodamus TEST merchant:790руб./30дней, payments_limit1, без recurring.
   Этот прогон не создавал checkout и не проверял списание/новый grant.
   Автопродление и реальная внешняя платёжная цепочка остаются неприёмленными.
3. **Тексты магазина и документов расходятся.** В товаре orderMethod=email-client,
   mailto:edemasanov2004@gmail.com и явная инструкция отправить письмо самому.
   В оферте и payment-refund написано про оплату цифровых товаров через Prodamus.
   Нужно согласовать копирайт с фактическим менеджерским процессом; это не
   заключение о соответствии законодательству. Новый checkout не предлагался.
4. **Ранее найденные счётчики статей.** Устаревание postCounts после изменения
   article до reload остаётся отдельной [правкой фронтендеру](../development/frontend-admin-article-invalidation-2026-10-25.md).
   Повторные изменения реального контента ради воспроизведения не выполнялись.

## Ограничения инструмента и честность измерений

Старая admin-вкладка3 осталась на native confirm предыдущего теста. Инструмент
не подтверждает нажатия и закрытие этого окна; новые вкладки позволяют навигацию
и чтение, но clicks не дают ожидаемых изменений. Даже закрытие PWA-подсказки
не состоялось. Это не доказанный дефект всех кнопок приложения. Запрошено ручное
закрытие старой вкладки/«Отмена»; обход через другой браузер или скрытый CDP не делался.
Гостевой loopback proxy имел только GET/HEAD, не пересылал cookies/authorization;
55requests/0upstream errors/0forwarded writes. Гостевая PWA-подсказка ограничила UI.

Предварительные ошибки измерителя исключены: img без src — lazy placeholders,
не доказанные broken files; ранние «desktop» замеры фактически были390px,
а helper после смены handle читал старую вкладку. Accepted manifest содержит
только отдельно проверенные route/width; первые loading-only снимки заменены
ready-проверками там, где требуется. Pending в хвосте viewport не объявлен
вечной загрузкой. Нулевой сетевой трафик/время кэша не измерялись.
