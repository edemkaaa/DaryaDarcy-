# Остановка API и передача фоновой работы — 6 ноября 2026

## Область проверки

Проверены два независимых процесса Node с настоящими Nest HTTP,
`WorkerJobs`, `IntervalJobs`, `registerApiShutdown` и MySQL-координацией из
production provider. База одноразовая, с полной цепочкой 52 миграций.
Доменная публикация заменена синтетической транзакцией в отдельной тестовой
таблице; остальные фоновые операции не запускаются. Платежей, писем и S3 нет.

Новых дефектов в выбранных сценариях не выявлено. Исполняемый код приложения,
SQL-миграции, фронтенд и API-контракт не менялись. Добавлены приёмочные тесты.

## Подтверждённое поведение

| Сценарий | Результат |
| --- | --- |
| SIGTERM во время задачи | Первый API перестаёт принимать новые соединения, ждёт задачу; второй отвечает через tRPC |
| Повторный SIGTERM | Не прерывает штатное ожидание |
| Блокировка при ожидании | Второй процесс не запускает ту же работу до завершения первого |
| Штатное завершение | Транзакция фиксируется один раз; процесс выходит с кодом 0; второй получает блокировку |
| Истечение дедлайна остановки | Процесс выходит с кодом 1; незавершённая транзакция откатывается; второй получает блокировку |
| SIGKILL | Незавершённая транзакция откатывается после закрытия соединения; следующий запуск работает |

Второй процесс запускает проверочную задачу через ту же production-операцию
координации. Проверка не ждёт следующего 60-секундного тика расписания;
она подтверждает возможность исполнения после освобождения lock, а не
гарантированное время подхвата реальной задачи.

## Оставшиеся ограничения и приоритеты

- **P1, перед выпуском:** проверить конфигурацию нескольких API на сервере:
  общий бюджет соединений, `API_COORDINATION_MODE=mysql`, число реплик,
  достаточное время остановки контейнеров и маршрутизацию на живую реплику.
  Локальная проверка двух процессов не заменяет эту проверку.
- **P2:** авария после принятия внешнего письма/платежного запроса, но до
  фиксации результата в БД, остаётся отдельным ограничением. SQL-откат не
  отменяет уже совершённый внешний эффект; exactly-once не заявляется.
- **Дополнено 9 ноября:** потеря только lock-соединения исследована отдельно;
  добавлен fail-stop после обнаружения. Окно до обнаружения и внешние эффекты
  сохраняют ограничения. [Результат](backend-worker-lock-loss-2026-11-09.md).
- **Следующий локальный срез:** пагинация при конкурентных изменениях
  публикаций, без изменения согласованного API по собственной инициативе.

Пуша и выкладки нет. Общий аудит остаётся открытым.
