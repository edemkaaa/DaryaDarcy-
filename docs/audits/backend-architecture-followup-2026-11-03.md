Для A4 есть отдельный [контракт и правила выпуска](../architecture/multi-api-coordination-2026-11-03.md).
По умолчанию остаются одна реплика и local-mode. Более одной требует mysql-mode;
неверная конфигурация/отсутствующая схема не допускают запуск listener. Legacy
SMS при нескольких репликах запрещён, а не объявлен распределённо защищённым.
Ни один HTTP-путь не использует старую синхронную квоту напрямую.

Общий счётчик не откатывается на локальную память при отказе SQL. Успешный пароль
не выдаёт cookie, если завершение лимита не подтверждено. Success старой попытки
не удаляет ни новую попытку, ни новый временной период с тем же номером попытки.
Ключи — SHA256; пароль, исходные email/IP и recovery proof в таблицу не пишутся.
Истёкшие служебные счётчики очищаются порциями, максимум 10000 на вид;
это не очистка файлов/загрузок/пользовательских данных.

MySQL lock держится на заимствованном соединении весь callback. Busy job
пропускается, ошибка lock не запускает работу. Неясный unlock уничтожает
соединение. Ожидание пула и SQL-команды ограничены; позднее полученное соединение
возвращается. Удерживаемое worker-соединение не означает exactly once при
сетевом разрыве во время внешнего эффекта; доменные receipts/транзакции сохранены.

| P2 | Пул всё ещё process-owned; db.ts и static compatibility factories остаются фасадами. Это осознанная совместимость, не полная provider/repository переработка. Нового поведения/ORM ради этого не добавлять. |

| P2, принятое ограничение | Push после публикации без durable outbox: сбой не откатывает публикацию, гарантированного автоматического повтора нет. Не относить сюда платёжные письма. |
