## Подтверждённый остаток фронта

Один актуальный [документ фронтендеру](../development/frontend-audit-final-handoff-2026-10-26.md).

1. Оглавление гида: после перехода Witchcore заголовок оказался примерно на
   281 px и был виден. У Castlecore после завершения движения заголовок оставался
   примерно на 933 px при viewport 720 px; промежуточные 8241 px не считаются
   установившимся результатом. Повторно подтверждена проблема неверной позиции
   при динамической загрузке предыдущих разделов, пункт 9 handoff остаётся открыт.
2. История оплат всё ещё явно сообщает «Последние 50 оплат». API paymentsPage
   готов, переход клиента не закрыт. На стенде 10 исходных оплат: потеря реальных
   старых строк в этом прогоне не воспроизводилась; нужны 51+ синтетических на
   отдельной БД, без создания платежей на стенде.
3. Остальные переходы на готовые page/receipt API из handoff не объявляются
   закрытыми одним этим браузерным прогоном.

## Не считать проверенным

- Кнопка блокировки: ввод причины через native window.prompt не был доступен
  в этом проверочном браузере, диалог не получен, запись не выполнялась.
  Отзыв по истечению доступа проверен отдельно и не заменяет manager block UI.
- Потеря ответа комментария проверена с автоматическим повтором того же ключа.
  Смена аккаунта выполнена после восстановления, с отдельным неотправленным
  текстом; переключение строго посередине неизвестной операции не воспроизведено.
- 22 VK запуска/звук/seek/fullscreen: provider не активировался, обход ранее
  полученного ограничения site-safety не выполнялся. Каталог не равен playback.
- Боевой Prodamus 790 ₽/автопродление и платёж → письмо: нет боевых настроек.
- Большие загрузки 32/80 МБ, нагрузка и физические устройства/PWA не повторялись.
  Пользователь отложил большие файлы; прежний положительный iPhone-отзыв не
  подменяет полную матрицу устройств. Пилот 5–7 дней остаётся отдельным этапом.
- Два старых публичных Yandex share отзывает владелец; в этом прогоне не менялись.
- Полный аудит безопасности Next и устранение оставшихся advisory не закрыты
  этой регрессией. Новых инфраструктурных сбоев БД намеренно не создавали.
