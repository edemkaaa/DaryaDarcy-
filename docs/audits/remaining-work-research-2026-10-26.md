## Порядок завершения

### R1. Настроить и принять боевую подписку — внешний блокер

Владелец кабинета передаёт закрытым файлом рабочие payform/secret/subscription ID/
subscription secret и подтверждает тариф790 ₽/месяц с recurring. Оператор сверяет
подпись/webhook/return/cancel до переключения. Настройки и код для TEST нельзя
выдавать за боевой запуск. Реальные списания требуют отдельного согласованного теста.

Приёмка: первая оплата → один аккаунт/срок/письмо → вход; повтор той же почты и
webhook без дублей/смены пароля; продление; отмена requested/pending → confirmed;
истечение доступа; заблокированный аккаунт не оформляет новый платёж.

**Отличие от буквального договора:** `identity/access.ts` отправляет одноразовую
ссылку установки пароля, а не готовый пароль в письме. Нельзя автоматически
считать такую замену принятой заказчицей. Зафиксировать согласие на текущий
безопасный способ либо отдельную точную правку; не рассылать пароли самостоятельно.

### R2. Закрыть старые публичные источники

После открытия защищённых PDF отозвать только shares:
[рецепты](https://disk.yandex.ru/i/nUoIS8gQ5VkClA) и
[Петербург](https://disk.yandex.ru/d/BM0uzv2cWZeM0Q).
Затем проверить их без входа. В этой сверке доступность shares повторно не
проверялась; подтверждения отзыва нет. Защищённые копии уже проверены.
Бесплатные Лошадку/тест/стилизации и публичные обложки не закрывать.

Позднее в исследовании скорости подтверждено одно старое фото post938,
target=club: анонимный S3 HEAD200 и optimizer GET200. Вся feed-папка не может
считаться гарантированно открытым контентом. Сначала составить адресную карту
legacy-клубных фото, затем согласованный перенос и закрытие старых URL;
не закрывать всю папку и не удалять исходники. Два Yandex shares — не полный
список оставшейся работы по прежним публичным источникам.

### R3. Принять настройки автоматической смены сезонов

Текущий fixed winter подходит для показа зимнего оформления, но не выполняет
автоматический переход. В режиме calendar существующие даты26октября выберут
осень, а зиму — с20ноября. Поэтому простое включение calendar прямо сейчас
противоречит ожиданию показать зиму. Согласовать дату старта/четыре даты и
переключить режим через штатную админку; проверить переходы по Москве на
одноразовой конфигурации, затем одну сохранённую рабочую настройку.
В рамках исследования настройки не изменялись.

### R4. Принять заказ из Магазина и блокировку из админки

Заказ: открыть цифровой товар → «Заказать через менеджера» → отправить письмо
в почтовом приложении → менеджер подтверждает товар/тему/получение. SMTP-тест
приложения не проверяет независимый почтовый клиент покупателя. Добавлять новый
сервер заказов без решения не требуется. Gmail SMTP Дарьи для текущего mailto
не нужен; смена менеджерского адреса — отдельная настройка владельца.

Блокировка: на явно тестовом участнике с синтетическим доступом принять native
prompt/причину, подтвердить отказ прежней сессии и checkout, удалить только
собственные fixtures. Ранее проверочный браузер не дал пройти native prompt;
это ограничение проверки, а не установленная ошибка интерфейса.

### R5. Принять 22 VK — внешнее воспроизведение

Для каждого видео записать ID, устройство/сеть, запуск, звук, перемотку и полный
экран; прежде всего61/62/65. Ранее62/65 показывали provider error в проверочном
браузере, пользователь подтвердил два ролика на iPhone без ошибки. Причина и
полная матрица22 не установлены. Запрет site-safety не обходить; для недоступной
проверочной среды результат получает владелец в обычном браузере. Не подменять
неработающий ролик чужим и не менять контент без подтверждения.

### R6. Устройства, нагрузка, пилот — ранее отложенная приёмка

Минимум по договору: iPhone/Safari, Android/Chrome, компьютер и запуск после
добавления на домашний экран. Проверить вход/возврат, разделы, фото/viewer,
VK/audio, комментарий/сохранение, закрытие клубного после окончания доступа.
Факт наличия manifest и одного рабочего iPhone не закрывает §4.16.

Нагрузку до100 одновременных и большие файлы проводить после решения по
ресурсам; текущий shared host почти заполнен. [DevOps-профиль](../operations/production-devops-handoff-2026-10-26.md)
подготовлен, не применён. Не увеличивать потолки контейнеров на4ГБхосте вслепую.
Пилот5–7 дней требует фактических дат, ответственных, журнала ошибок и результата;
готовый план пилота не считается проведённым пилотом.

## Дополнительный технический остаток аудитов

Эти пункты не следует смешивать с установленными поломками функций договора:

- **Legacy полные чтения ещё доступны.** В routers остались `feed.list`,
  `feed.userInteractions`, `feed.savedPosts`, `admin.members`, `admin.articles`
  и другие совместимые методы. Текущий frontend перешёл на page/batch API,
  но tooling/candidate smoke и тесты ещё вызывают старые. Это незавершённый
  retirement из B03/BE03, а не прежняя проблема742постов при открытии админки.
  Сначала инвентаризация поддерживаемых клиентов/операторских инструментов,
  затем отдельный совместимый выпуск; нельзя молча обрезать массив до первых N.
- **Public avatar/cover unknown operation:** новая receipt/status связка есть;
  локальные HTTP/SQL и synthetic browser пройдены. Не повторён полный frontend →
  настоящее API → Timeweb сценарий потери ответа, смены аккаунта посередине
  неизвестной операции, нового аватара до старого ответа и отзыва роли.
  Изменение аватара/имени прямо исключено §3.1, но пользователь отдельно заказал
  исправление; это самостоятельная приёмка, а не новый обязательный блок договора.
- **32/80 МиБ:** согласованные лимиты приложения, не буквальные размеры договора.
  Максимумы/пик памяти и качество сложных реальных фото остаются отложенными.
- **Восстановление:** backup последних41таблицы проверен на сервере и Mac,
  fresh-install44миграций проверен; полная репетиция восстановления этого нового
  снимка44миграций отдельно не подтверждена. Репетировать только на отдельной БД.
- **Orphan cleanup B05:** receipts не равны безопасной сборке мусора. Новая ручная
  очистка публичных orphan-объектов не реализована/автоочистка не включена.
  Она не нужна для запуска основного пользовательского пути и требует отдельной
  согласованной операции; старые S3-файлы ради закрытия аудита не удалять.
