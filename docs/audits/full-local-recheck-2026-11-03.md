### Подтверждённый frontend-remount, без изменения дизайна

горизонтальных фото `landscapePair` переводит число колонок с двух на одну;
`sizes` меняется, оба узла изображения заменяются при прежних URI.
Источник: `shared/media/image.tsx`, `features/club/club-post-photos.tsx`,
`shared/media/natural-photo-stack.tsx`. Диагностический маркер старого узла исчезает;
HTTP-перехватчик видит последовательность `0.svg, 1.svg, 0.svg, 1.svg`.

Проверки геометрии проходят; не проходит исходное требование ровно двух запросов.

S3 этим не доказан. Замена DOM подтверждена отдельно. Не запрещать нужную загрузку
более качественного responsive-превью и не фиксировать старый `sizes` ради GREEN.
Точная задача и критерии добавлены в единый документ фронтендеру.

## Native browser + API + SQL

Отдельно выполнены 117 старых сквозных сценариев через настоящий локальный backend,
новую MySQL, production frontend и перехватчик SMTP: **54 passed, 63 failed**.
Первый запуск имел ошибку harness (URL без завершающего `/`); он не использован
для вывода об ошибках продукта. Приведены результаты повторного корректного запуска.

Уже установлены причины части отказов:

1. `tests/helpers/club-service-access-browser-cases.ts:127` всё ещё требует полного запрета
   профиля без оплаты. Это расходится с принятой доступностью открытого «Сохранённого».
2. `tests/helpers/quiz-browser-cases.ts:961` требует неизменного `sessionVersion` после logout.
   Серверный отзыв сессий согласован и должен менять эту версию; email/phone/role/password
   и оплаты при этом следует проверять отдельно, не убирать их проверки.
3. Несколько comment-сценариев пытаются нажимать вкладки под открытой настройкой профиля.
   Старая localStorage-метка в fixture не завершает новый сценарий настройки.
   Force-click и отключение диалога не являются исправлением.
4. Глобальные текстовые локаторы находят скрытую сохранённую страницу и видимую страницу одновременно.
   Нужно обращаться к активному экрану, сохраняя проверку видимости/доступа.
5. Старые сценарии привязки почты требуют UI для legacy телефонных аккаунтов.
   Владелец ранее отказался включать эту функцию. Не восстанавливать её ради теста;
   сначала отделить действующие пользовательские сценарии от исторической приёмки.

Остальные ошибки этого набора ещё требуют узкого воспроизведения с актуальными
входными данными и проверкой HTTP/SQL. Все 63 не объявляются тестовым долгом автоматически.

## Что исправлено в самих проверках

- Успешные fixtures дополнены реальными обязательными nullable-полями `media`,
  `publishedAt`, `richText`, `commentCount`, `contactPhone`, `coverUrl` и полями video DTO.
  `userName/avatarUrl` в комментарии заменены на `authorName/authorAvatarUrl`.
- Уведомления редактора ищутся в `[data-background-notice] [role=status]`;
  сохранены проверки отказа, недоступности действий, исходных bytes/key и количества записей.
- Quiz reload ждёт подтверждённого выбранного ответа: UI показывает его только после storage lock/write.
- В тесте зависшего фото используется DOMContentLoaded: полная загрузка документа
  намеренно не завершается до работы механизма timeout/retry. Сохранены проверки
  отмены старого body, ровно двух запросов и кешированного reload.
- Ожидание 45 миграций обновлено до текущих 50 в трёх opt-in SQL-наборах.
  Миграционные файлы, история рабочей БД и защитные проверки не изменены.
- Проверка гостевой Библиотеки ограничена активным patterns-экраном;
  запрет запросов списка/оригиналов сохранён.

Нет ослабления runtime-валидаторов, новых исключений доступа, force-click,
новых автоматических повторов записи или удаления отрицательных проверок.
