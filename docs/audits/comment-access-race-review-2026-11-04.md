# Доступ к посту при отложенной записи комментария

4 ноября 2026. Исходная версия 06bcdbe3, исправление проверено локально.

Обычный addComment проверял доступ в service, затем в транзакции сверял
сессию и публикацию, но не новый target, подписку и срок комментариев.
Update/delete/like/report после предварительного чтения тоже не перепроверяли
доступность поста. Это оставляло окно между авторизацией и записью.

Один исходный случай воспроизведён отдельно на настоящих router/SQL без
подмены политики. Запрос начинает выполняться для открытого поста, ожидает
users-блокировку, пост переводится в club. После снятия блокировки старый
код сохраняет комментарий для пользователя без подписки. Контрольный тест
на отказ завершился RED с полученным comment ID. Лог red-one.log сохранён.
Первый широкий прогон содержал также ошибки тестового контроля SQL-ожидания
и не считается доказательством 16 отдельных дефектов. Контроль исправлен
сопоставлением BLOCKING_THREAD_ID с performance_schema.threads.PROCESSLIST_ID.

Исправление повторно проверяет текущий пост под share-блокировкой перед
изменением комментария. Для клубного поста подписка читается текущим locked
read в той же транзакции. Общая политика применяется также к приватному пути.
Для update/delete/like/report сохраняется порядок user, post, comment,
совместимый с каскадным удалением поста. Внутренние вызовы с числовым ID
сохраняют прежнее поведение, HTTP передаёт доверенный actor с epoch.
Срок 48 часов перепроверяется при добавлении, а не добавляется к редактированию.

Проверки на одноразовой MySQL после 51 штатной миграции завершились успешно.

- 16 случаев SQL-гонки охватывают пять операций и переход в club, draft,
  отзыв подписки. Дополнительный случай проверяет закрытие срока при добавлении.
  После отказа тексты, лайки и жалобы совпадают с исходными.
- Общий прогон шести SQL-файлов прошёл 135/135 за 9,55 с, включая приватные
  файлы на loopback SDK wire, HTTP/JWT комментарии и прежний retirement.
- 13/13 проверок доступа без MySQL, типы, lint и прежний API-контракт проходят.

Логи и runner находятся рядом с репозиторием в
`../.local-artifacts/comment-access-race-20261104`. Каждый созданный контейнер
принадлежал runner и удалён с одноразовыми данными. S3/SMTP/рабочая БД не использовались.
Результат не заменяет новый образ и его HTTP-приёмку перед выпуском.
Публичный контракт не менялся, новой задачи frontend нет.
