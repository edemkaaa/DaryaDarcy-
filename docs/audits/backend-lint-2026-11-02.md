# CQ-1: проверка качества бэкенда, 2 ноября 2026

Реализовано локально после аудита `ac413024`. Пуша/выкладки нет; фронт,
рабочая БД, S3, настройки сервера и админские входы не менялись.

## Что изменено

- `pnpm lint:backend` проверяет все 241 TS-файл backend/src, ошибки и предупреждения
  блокируют команду. Корневой `pnpm lint` последовательно запускает backend и frontend.
  GitLab уже вызывает эту команду: отдельная дублирующая CI-задача не нужна.
- Включены пять правил корректности: floating/misused promises, async executor,
  возврат значения из executor и изменение результата из finally.
  Массовых стилевых требований и автоформатирования старых файлов нет.
- `typescript-eslint@8.71.0` объявлен прямой dev-зависимостью. Используется уже
  установленная/зафиксированная версия, других обновлений пакетов нет.
- Типизированный lint наследует compilerOptions проекта, но начинает обход только
  с backend/src через `apps/backend/tsconfig.eslint.json`. Импортируемые сервером
  модули продолжают разрешаться; тесты и фронт не являются отдельными точками входа.

## Первоначальные пять замечаний

1. Два асинхронных middleware загрузок и legacy YouTube handler передавались напрямую
   в Express 4. Добавлена общая маленькая обёртка `asyncHandler`: rejected Promise
   передаётся в `next(error)`. Существующие ответы, проверки доступа, ограничения
   размера и завершение потока сохранены; непредвиденная ошибка не теряется.
2. В backup намеренно сохранён приоритет ошибки удаления временных файлов с паролем.
   Для одного throw в finally есть пояснённое исключение. Логика бэкапа не менялась.
3. Для одной команды установки UTC у MySQL оставлено пояснённое исключение:
   установленный mysql2 PromisePool пересылает событие connection с исходным callback
   connection (проверены `lib/promise/pool.js` и `inherit_events.js`), хотя его типы
   обещают Promise. Не добавляли `.catch()` к объекту, который не является Promise.

Отключений правила на файл/проект нет. Неиспользованные eslint-disable теперь ошибка.
По умолчанию правило floating promises допускает явный `void`; оно не доказывает,
что вся фоновая работа безопасна. Проверка обработки ошибок в таких местах по-прежнему
остаётся частью ревью. Legacy any и неиспользованные импорты этим этапом не охвачены.

## Проверка

- 79 тестов в 8 файлах прошли: lint, asyncHandler, request bodies, реальные
  HTTP/Nest/private-upload проверки, lifecycle YouTube, HTTP security и CI-конфигурация.
- Новый HTTP-тест искусственно выбрасывает ошибку при разборе метаданных после
  успешной аутентификации. Получен 500 с обычным `Internal server error`, без
  подробностей, без обращений к рабочей БД или S3.
- Контрольная мутация: временное удаление `.catch(next)` приводит к таймауту этого
  теста и unhandled rejection. Файл восстановлен побайтно; затем целевой прогон зелёный.
- Тест конфигурации запускает настоящий ESLint на ошибочных примерах и подтверждает
  срабатывание всех пяти правил. Пример с await/catch проходит. После сужения
  tsconfig этот тест и полный backend lint повторены успешно.
- Типы backend/shared/frontend/E2E, backend build, API107 (46 501 байт), boundaries887,
  frontend lint прошли. `pnpm install --lockfile-only --frozen-lockfile --offline
  --ignore-scripts` подтвердил согласованность manifests/lockfile.
- Полный SQL/browser-набор и внешний CI в этом этапе не запускались. Миграций нет;
  SQL и работа резервного копирования изменены только поясняющими комментариями.
