# Передача фронтендеру по Библиотеке и загрузкам

Дата: 20 октября 2026 года. Фронтенд ведёт фронтендер; агент выполняет только
backend-задачи и готовит документы для интеграции. Дизайн менять не требуется.
Этот документ уточняет текущие задачи по Библиотеке и загрузкам, а не поручает
повторную реализацию уже работающего фронта.

Уточнение пользователя: «Сборник рецептов» и «Гид по Петербургу» пока оставить
как есть. Этот документ не поручает менять их карточки, ссылки или выдачу.
Четыре зимние выкройки должны быть доступны участницам клуба и администратору,
но не гостям. «Лошадка» рассматривается отдельно: её платный статус не подтверждён.

## Что сейчас не закрыто

По проверке пользователя на стенде семь эстетик доступны администратору с HTTP
200, но список выкроек после входа возвращает 404: карточки отсутствуют, PDF
отключён. Старый публичный файл по-прежнему доступен гостю. Это разрыв выпуска:
новый экран уже установлен, а выдача реальных выкроек не подготовлена. Ошибка
не доказывает проблему входа или отсутствие подписки.

API эстетик и API файлов независимы. Для файлов нужны оба серверных флага
`PRIVATE_LIBRARY_FILES_ENABLED` и `PRIVATE_CONTENT_FILES_ENABLED`, а также
готовые привязки к закрытым объектам. Повторная проверка сервера20 октября
подтвердила: Library flag false, content flag true, pattern bindings0
(включая все4 winter keys). SQL выполнялся в read-only transaction. Включить
один флаг без подготовки данных недостаточно; это подтверждённый backend-блокер.

Загрузки постов, статей и комментариев включены после проверки хранилища.
Первый реальный прогон подтвердил запись девяти тестовых файлов и повторы без
дублей, но остановился на проверке выдачи. Полная приёмка чтения, отзыва доступа
и предельных размеров ещё открыта. Тестовые данные удалены; причина остановки
не установлена. После смены VPN SSH/HTTPS восстановились; прежний U1 image
healthy, четыре upload/delivery flags true. Сам опубликованный read-сценарий
ещё не повторён: прежний helper пишет в рабочую БД, что пользователь запретил.
На отдельной одноразовой БД текущая Библиотека прошла4 native API/S3 сценария
с6 новыми synthetic files, exact cleanup/HEAD404 и неизменной policy. Это не
перенос реальных выкроек и не полная приёмка опубликованных загрузок. Отдельный
content-upload S3 прогон дважды остановился на timeout ещё до создания fixtures;
его4 сценария skipped. Ни source данных, ни дизайн/код frontend не менялись.

## Что должен завершить бэкенд

1. Сверить фактическую версию API, флаги и схему на стенде, не меняя текущую БД
   или админский вход. Найти точную причину остановки проверки выдачи загрузок.
2. Для зимних выкроек подготовить проверяемый перечень четырёх изображений
   `holly`, `sock`, `star`, `apple`. После отдельного согласования переноса
   создать закрытые копии и привязки, проверить содержимое и типы. PDF `loshadka`
   не включать в этот перенос до решения о его бесплатной/клубной доступности.
3. Проверить готовые данные и выдачу, затем согласованно включить Библиотеку и
   передать фронтендеру результаты приёмки. Успех API эстетик не заменяет её.
4. Отдельно согласовать закрытие точных старых originals/derivatives и очистку
   контролируемых кэшей. Не закрывать весь каталог картинок и общие обложки.
   Старую Яндекс-ссылку должен ограничить её владелец; backend API не отзывает
   доступ к чужой публичной ссылке или уже скачанным копиям.

Перенос рабочих файлов, запись привязок и закрытие старых источников не считаются
разрешёнными одним поручением «делать backend». До согласования их не выполнять.

## Существующие контракты Библиотеки

| Запрос                                           | Успешный результат                           | Важное условие                                          |
| ------------------------------------------------ | -------------------------------------------- | ------------------------------------------------------- |
| `GET /api/library/guides/aesthetics/:key`        | `{key,style,space,rituals,blog,inspiration}` | Живая сессия и доступ к клубу; отдельный API текстов    |
| `GET /api/library/materials/patterns/files`      | `{files,nextCursor}`                         | Включённая выдача и привязки; до 50 записей на странице |
| `GET /api/media/library-files/patterns/:fileKey` | Байты файла; также HEAD и Range              | Повторная серверная проверка доступа при чтении         |

Элемент `files` содержит `fileKey`, `sortOrder`, `revision`, `filename`,
`mimeType`, `fileSize`, `url`. Следующая страница запрашивается с полученным
`cursor`; `nextCursor: null` завершает список. Для зимнего набора ожидаются
четыре ключа выше с MIME JPEG, PNG или WebP. Существующий wire-контракт допускает
также PDF `loshadka`, но это не решение сделать «Лошадку» платной.
Принимать только canonical URL `/api/media/library-files/patterns/:fileKey`.

Для этих read API ответ 404 может означать закрытую функцию, отказ доступа или
недоступный материал; это не универсальное доказательство выхода из аккаунта.
503 означает временный серверный сбой. Успешный пустой список тоже не доказывает
готовность пяти выкроек. Ответы закрытых материалов имеют `private, no-store`.
Форма текстов определена в [общей схеме](../../packages/shared/src/aesthetic-guide.ts),
файлов — в [существующем контроллере](../../apps/backend/src/content/library-files.controller.ts).

Локальный backend follow-up20 октября (ещё не выпущен): shared private read
добавляет расширение к generic имени в `Content-Disposition`, например
`attachment; filename="file.pdf"` или `inline; filename="file.webp"`.
Для post media label остаётся `attachment-ID`, для Library — `fileKey`.
Расширение определяется сохранённым MIME, не original filename и не S3 path;
нормализованное фото остаётся WebP. JSON API, URL, права и статусы прежние,
перегенерация клиентского контракта и изменение дизайна не нужны. При интеграционной
приёмке проверить сохранение PDF/документов с расширением и прежний inline просмотр.
Это не исправление Library404 и не объяснение незавершённой live U1 read-проверки.

## Что проверить и при необходимости исправить фронтендеру

- Сверить уже отправленные изменения Библиотеки и загрузок с собственной
  актуальной веткой. Не откатывать весь фронт и не повторять готовую интеграцию.
- При 404 или 503 списка выкроек показывать существующее состояние недоступности
  и повторного чтения. Не очищать подтверждённую сессию и не считать активную
  участницу гостем только из-за ответа файлового API.
- Различать недоступный список и отсутствующий отдельный файл. До получения
  проверенной привязки действие с зимней выкройкой недоступно. Отсутствие PDF
  «Лошадки» не должно блокировать четыре готовых зимних изображения.
- Отдельно сверить статус «Лошадки»: исходный b06a46a содержал
  `isClubOnly: false`, а 2fede81 перевёл карточку на закрытый patterns screen.
  Не считать это согласованным изменением платности. После решения восстановить
  согласованный доступ отдельно от четырёх зимних выкроек, сохранив дизайн;
  текущий backend-only агент frontend не меняет.
- Не добавлять обход на прямой S3, старые static URLs или платные тексты в JS.
  Сохранить бесплатный тест, его расчёт, публичные обложки и оформление.
- При смене аккаунта, отзыве доступа или уходе со страницы отменять запросы и
  убирать прежние закрытые данные/источники. Поздний ответ другого аккаунта
  не должен повторно открывать материал. Проверить уже реализованные guards.

Блокер подготовки настоящих выкроек остаётся у бэкенда и владельца источников.
Фронтендер не должен исправлять его ослаблением проверок доступа.

## Доступность и восстановление загрузок

`GET /api/capabilities` возвращает существующие boolean поля:
`privateContentUploads` для фото постов/статей/комментариев и документов статей,
`privatePostMediaUploads` для аудио/документов постов,
`privatePostVideoUploads` для видео. Для видеопостера дополнительно требуется
`privateContentUploads`. Отсутствующее/невалидное поле и ошибка чтения не дают
разрешения загрузки. Значение true — флаг выпуска, не проверка здоровья S3.

Проверить свежий read перед выбором и отправкой нового файла; при недоступности
сохранить исходный File, данные формы и ключ восстановления. Текст, VK и
работа с уже выбранными элементами не должны зависеть от нового upload.

Использовать существующие пары методов:

- `admin.uploadPrivateContentFile` / `admin.privateContentFileStatus`;
- `admin.uploadPrivateAttachment` / `admin.privateAttachmentStatus`;
- `club.uploadPrivateCommentPhoto` / `club.privateCommentPhotoStatus`;
- raw `POST /api/admin/private-video-uploads` с `Idempotency-Key` /
  `admin.privateAttachmentStatus`.

После потери ответа сначала читать статус прежнего ключа. Явный повтор сохраняет
исходные байты и payload; новый ключ не создаётся для неизвестного результата.
Файл считается частью материала только после подтверждённого сохранения поста,
статьи или комментария. При отмене неизвестного сохранения обновить список по
реальному результату; позднее обновление не применять в другом аккаунте/экране.
Лимиты исходных байтов: фото 4 МиБ, аудио/документ 32 МиБ, видео 80 МиБ;
Base64 увеличивает размер JSON. Полные границы на стенде ещё требуют проверки.

## Критерии совместной приёмки

- [ ] Для участницы с действующим клубным доступом и администратора доступны
      все четыре правильные зимние привязки; изображения открываются через API.
- [ ] Статус и доставка «Лошадки» отдельно сверены и согласованы; её отсутствие
      не блокирует зимний набор, а технический перенос не меняет платность.
- [ ] Гость, неоплаченный пользователь и аккаунт с отозванным доступом не получают
      закрытые материалы. Смена аккаунта не оставляет содержимое предыдущего.
- [ ] 404, 503, пустые/неполные данные и повторное чтение не создают ложный logout,
      ошибочную выдачу или публичный fallback.
- [ ] Оба редактора, статья и фото комментариев проходят upload → save → read;
      потеря ответа/reload/повтор не создают второй файл или материал.
- [ ] Чтение файлов проверено через GET, HEAD и Range, включая отзыв доступа;
      проверены форматы, размеры и удаление геометок фотографий.
- [ ] По согласованному списку старые публичные источники закрыты, а бесплатные
      материалы и обложки работают. До этого полную защиту Библиотеки не заявлять.

При передаче результата указать версии фронта/API, проверенные роли и сценарии,
отдельно отметить подставные ответы и настоящие API/БД/S3. Пароли и ключи в
документ не включать. Реальные платежи и внешние письма для этой проверки не нужны.
