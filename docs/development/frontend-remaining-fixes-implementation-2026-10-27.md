# Реализация оставшихся правок фронтенда, 27 октября

По документу «Daryadarcy — оставшиеся правки фронтенда», сверявшему 341b9d9.

## Дополнительные исправления повторного аудита

После повторного аудита реализовано сохранение черновиков статей в IndexedDB
вместе с выбранными файлами. Черновики разделены по аккаунту и статье;
проверка ревизий не позволяет другой вкладке затереть более новую запись.
Неизвестный результат изменения статьи сохраняет блокировку повторной записи
после перезагрузки. При отказе хранилища редактор сообщает об ошибке.

Тест восстанавливает ответы и текущий вопрос; данные привязаны к аккаунту
и версии вопросов. Редакторы профиля показывают ошибки локального хранения,
а изменение профиля не отправляется без сохранённого ввода для восстановления.
Подсказки размещения статьи согласованы с существующим поведением API.

Проверка старых изображений отклоняет неоднозначные формы URL до нормализации
Next.js. Защита по-прежнему выключена. Интерфейс скрывает отложенный SMS-вход,
даже если старый сервер объявляет его доступным; сетевой контракт сохранён.

Запрос admin.postCalendar за два месяца отправляется отдельно с пределом URL
8192 символа и maxItems=1: он не помещается в обычные 2048 символов. Остальные
пакетные запросы сохраняют ограничение 2048 символов и maxItems=20.

Итоговые проверки перед восстановлением сессии: TypeScript приложения/E2E,
ESLint, production-сборка и 114 целевых модульных тестов прошли. Общий браузерный
прогон завершился с 97 успешными и 3 неуспешными сценариями; после исправления
ожидания карусели отдельный прогон всех трёх и смежных сценариев прошёл
13/13, включая новый сценарий двух отдельных черновиков статей. Всего проверен
101 сценарий; это не единый чистый прогон всей E2E-сюиты.
Исходники фронтенда после восстановления сессии побайтово совпали с копией,
на которой выполнялись последние проверки. Изменения остаются локальными.

  интерфейса выведен из существующего AuthUser с преобразованием даты.

  доступа он проверяет новое чтение разрешения и отсутствие повторной загрузки.

Прошли 41 проверка хранения/контроллера/провайдера сессии, включая Chromium
с текущим AuthProvider, и 10 E2E-сценариев исправленных фикстур. E2E использовали
ранее собранные локальные production-копии обычного фронтенда и VK-каталога;
полная пересборка после удаления дублирующего состояния не выполнялась.
TypeScript приложения/E2E и ESLint фронтенда после этих правок проходят.
Команды запускались последовательно в группе с лимитом памяти 1 ГиБ и остановкой
при общей занятой ОЗУ 13,2 ГБ. Коммитов и выкладки нет; CI, backend и видеосервис
этими правками не изменялись.

## Исправления по исходному списку

### Версии редактирования и предел текста по новой передаче

Обычный и быстрый редакторы постов, редактор статей и изменение тегов сохраняют
непрозрачную editRevision из полного detail. Исходный снимок и версия остаются
в журнале того же аккаунта, включая статью с приватными файлами и загрузку
обложки. Восстановленный старый черновик не заимствует версию нового GET.
При update передаётся expectedRevision; фоновые чтения версию редактора не меняют.

После 409/412 текущий ввод и файлы сохраняются, повторная отправка блокируется.
Можно прочитать серверную запись для сравнения. Отдельное подтверждение после
сравнения разрешает продолжить с выбранной версией, но ничего не отправляет;
сохранение требует нового действия. Неподтверждённый запрос с ещё прежней
серверной версией остаётся заблокированным. При совпадении доказуемых полей
результат подтверждается чтением без повторного mutation. Неэкспонируемые
private binding ID не считаются доказанными только по совпадению текста.

После подтверждённого изменения detail перечитывается. Отказ этого чтения
не превращает ACK в разрешение повторить запись. Текст поста проверяется
TextEncoder до загрузок/отправки: максимум 65 535 байт UTF-8; черновик допускает
более длинный ввод и сохраняет его для исправления. На JSON статей этот предел
не распространяется. confirmPost/deleteMedia сохраняют прежний контракт.

Сгенерированный contract.ts не переписывался вручную: поля editRevision и
expectedRevision получены из origin/staging в49a6d63. Граница edit-revision.ts
проверяет версии при чтении и сохраняет совместимость со старыми журналами.
После обновления репозитория типы фронтенда/E2E с новым контрактом проходят.
Строгий серверный режим здесь не включался, backend, CI, S3 и стенд не менялись.
Браузерные проверки нового протокола используют синтетические ответы API;
совместный выпуск фронтенда с настоящим сервером требует отдельной приёмки.

152 целевые модульные/Chromium-проверки прошли, в том числе настоящий IndexedDB
для версий и байтов файлов во всех трёх журналах статьи и изоляции аккаунтов.
Восемь новых E2E редакторов и один существующий сценарий быстрого редактора
прошли на локальной production-сборке; два из них перезапускались после
исправления неоднозначного тестового селектора. Финальная production-сборка,
линтер и границы модулей проверены после последних правок восстановления тегов.
Проверки типов фронтенда/E2E и новых тестовых модулей проходят. Полная проверка
типов монорепозитория остановилась на заданном лимите heap 640 МиБ; она не
подменяется этими целевыми проверками. Сборка выполнялась с одним worker
и жёстким лимитом группы до 1,75 ГиБ; общий сторож останавливает команды
при занятой ОЗУ 13,2 ГБ. Эти проверки выполнены до коммита и выпуска фронтенда.

- tRPC GET-пакеты ограничены 2048 символами URL. Текущие параметры и ID кодируются
  в ASCII; для них это также предел байтов. Ограничение числа процедур 20 сохранено.
  Отмена отдельной операции отсекает её поздний ответ, не отменяя соседей в пакете;
  смена аккаунта отменяет все запросы прежней сессии.
- Для админской миниатюры задано 56px, для «Сохранённого» — 31% от канвы
  за вычетом 40px отступов, для карусели статьи — 58% канвы (максимум 480px).
  Качество 75, режим крупного просмотра и исключение защищённых URL из optimizer
  сохранены. Публичные фото в viewer по-прежнему выбирают отдельный крупный
  ресурс по sizes=100vw; защищённые источники обходят публичный optimizer.
- RAW 429 сохраняет проверенный Retry-After. Срок ручного повтора записывается
  вместе с исходным File/ключом в черновик. Оба редактора используют одну кнопку
  восстановления с отсчётом; до срока даже прямой вызов восстановления не отправит
  запрос. После срока — только ручное действие, сначала status, затем прежний ключ.

## Выключенная защита клубных источников

`src/shared/security/legacy-club-images.ts` вызывается из существующего proxy
до раннего пропуска `/_next/image`. CSP, API proxy, matcher и защита Библиотеки
сохранены. Включение **не выполнялось**. Прямые URL на домене S3 этот proxy
перехватить не может: их отзыв остаётся отдельным действием оператора хранилища.

Конфигурация только сервера, без NEXT_PUBLIC и без клиентских capabilities:

- `LEGACY_CLUB_IMAGE_GUARD_ENABLED`: только точное `true` включает проверку;
  по умолчанию и в примере окружения — выключено.
- `LEGACY_CLUB_IMAGE_MANIFEST_PATH`: абсолютный путь к закрытому файлу,
  смонтированному вне каталога приложения, public и Git.
- `LEGACY_CLUB_IMAGE_MANIFEST_SHA256`: SHA-256 точных байтов согласованного файла.

Ожидается JSON version=1 с endpoint=`https://s3.twcstorage.ru`,
bucket=`daryadarcy-s3`, непустым `denyKeys` и массивом `preservedKeys`.
Ключи — точные декодированные пути внутри бакета. Дубликаты, пересечения,
dot-segments, управляющие символы, обратные слеши и неоднозначные `%`-ключи
отклоняются. Unicode, обычное percent-кодирование, порт443 и query-варианты
поддерживаются. Неизвестные и общие публичные ключи не блокируются.
Список и его реальный digest ещё должен передать оператор; в репозиторий
включены только синтетические тестовые значения.

Выключенная проверка не читает manifest. При включённой проверке ошибка файла,
версии, digest или пересечение списков дают 503/no-store для optimizer; точное
совпадение — 404/no-store, некорректный URL — 400/no-store. Ошибки не раскрывают
ключи или серверный путь. Валидированные правила кешируются по пути/digest;
изменение согласованного набора требует нового digest и перезапуска выпуска.

Будущая активация требует отдельного согласования, проверки всех новых привязок,
двух общих обложек и бесплатных материалов, адресной инвалидации производных
в кеше и отдельного отзыва исходников в S3. Не включать для ускорения этой приёмки.
