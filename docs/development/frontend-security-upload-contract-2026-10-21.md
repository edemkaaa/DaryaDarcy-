# Фронтендеру: закрытие legacy-загрузок и явные публичные обложки

## Статус и границы

21 октября пользователь согласовал `purpose="publicCover"` для публичной загрузки
обложек. Изменения бэкенда локальные: не выпущены на стенд. Фронт/дизайн, рабочая
БД, S3/policy и существующие файлы не менялись. Возможность смотреть старую
публичную копию этим исправлением не закрывается; её перенос согласуется отдельно.

Не добавлять альтернативное публичное хранилище, автоматическое переключение
на старые процедуры или новую загрузку при неизвестном результате предыдущей.

## Что изменить

| Назначение | Использовать | Что больше не работает |
| --- | --- | --- |
| Публичная обложка статьи | `admin.uploadPhoto` с `purpose: "publicCover"` | Запрос без назначения или с назначением закрытого фото |
| Аватар | Прежний `profile.uploadAvatar` | Не добавлять `publicCover` в запрос аватара |
| Фото поста/статьи, документ статьи | `admin.uploadPrivateContentFile`, существующие `usage` и status/recovery | Использование `admin.uploadPhoto` для тела материала |
| Фото комментария | `club.uploadPrivateCommentPhoto` с `postId`, ключом и `usage: "commentPhoto"` | `club.uploadCommentPhoto` |
| Аудио/документ поста | `admin.uploadPrivateAttachment` и прежний status/recovery | `admin.uploadMedia` |
| Видеофайл поста | `POST /api/admin/private-video-uploads` и прежний status/recovery | `POST /api/admin/upload-video` |

VK-ссылки/плеер, публичные обложки и просмотр существующих URL не запрещаются.
Квоты, feature flags и срок восстановления не меняются. Capability разрешает
интерфейс загрузки, но не доказывает здоровье S3 или право на конкретный пост.

### Публичная обложка

В [articles-admin.tsx](../../apps/frontend/src/features/admin/articles-admin.tsx)
ветка `uploadImages(..., publicCover=true)` сейчас отправляет результат
`fileToUpload` без назначения. Только в этой ветке передать:

```ts
await utils.client.admin.uploadPhoto.mutate(
  { ...payload, purpose: "publicCover" },
  { signal: task.signal },
);
```

Успех по-прежнему `{url: string}`. Отсутствующее/другое назначение даёт400 без
записи объекта. Администратор обязателен; обычный пользователь/модератор не
получает право на обложки от передачи поля. Фото остаётся JPEG/PNG/WebP до4МиБ,
перекодируется в WebP с удалением метаданных. Новый публичный namespace `covers/`;
не анализировать ключ на клиенте. Назначение является явным выбором публикации,
а не способом защиты загруженного объекта.

### Удалить доступность старых путей, не дизайн

В [admin-post-editor.tsx](../../apps/frontend/src/features/admin/admin-post-editor.tsx)
и [create-post-modal.tsx](../../apps/frontend/src/features/admin/create-post-modal.tsx)
ещё передаются adapters `upload` на `admin.uploadMedia`. Проверить их реальные
потребители и убрать достижимый fallback; существующие `uploadPrivate` уже есть.
Само наличие callback не доказывает, что он вызывается текущим сценарием.

[video-upload.ts](../../apps/frontend/src/features/admin/media/video-upload.ts)
содержит прежний `uploadAdminVideoBlob`. Не использовать его как запасной путь
при404/таймауте закрытой загрузки. Старые legacy routes теперь всегда404,
включая выключенные private flags, неправильный body и batch с другим запросом.
Отказ до tRPC может быть обычным JSON `{error: string}`, а не tRPC envelope:
нельзя отображать техническое `Unable to transform response` вместо объяснения.
404 загрузки не является доказанным выходом из аккаунта.

Перед обновлением frontend-контракта выполнить `pnpm api:contract` на согласованной
версии бэкенда. В этом backend-only изменении generated frontend file намеренно
не обновлён: `pnpm check:api` сообщает расхождение. Не подавлять проверку, не
менять backend-модель ради совместимости со старым небезопасным запросом.
Генерация в отдельный локальный артефакт без записи во frontend подтвердила:
единственное расхождение wire types — обязательное `purpose: "publicCover"`.

## Проверить на фронте после подключения

1. Обложка с явным назначением загружается; ошибка/отмена не очищает выбранный файл.
2. Закрытые фото/аудио/документы/видео обоих редакторов и фото комментариев не
   вызывают ни один legacy route, в том числе после таймаута и выключения флага.
3. При потере ответа сначала status с прежним ключом, затем безопасный повтор;
   смена аккаунта не использует чужой receipt/ключ/незавершённый callback.
4. Для отказа403/404 нет публичного fallback, очистки сессии или ложного успеха.
5. Аватары, старые публичные обложки и бесплатные материалы отображаются как раньше.

Backend-проверки не заменяют браузерную/мобильную приёмку; последние здесь не запускались.

## Pen Pals: существующий контракт ответов

Флаг не включался. `requestMatch` и `respondMatch` теперь проверяют активные
анкеты и свежую блокировку аккаунтов транзакционно. Чужая/недоступная заявка404,
просроченная незавершённая409, malformed ID400. Повтор не продлевает срок7дней;
уже взаимно подтверждённая пара не истекает из-за этого срока. Участник может
отклонить свою заявку, даже если анкета больше не активна. Формы успеха прежние:
`{matchId}` и `{ok:true}`. Не превращать409 в повтор с новым ключом/продлением.
