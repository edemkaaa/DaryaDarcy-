## Подключённые методы и сохранённые сценарии

| Методы                                                                        | Поведение фронтенда                                                                                                                                                                                                                                                                |
| ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `club.subscription`                                                           | Серверный `hasClubAccess` отдельно от оплаты. Служебный доступ без автопродления, реальный оплаченный срок, прежнее исключение owner. Ошибка чтения не выдаёт доступ.                                                                                                              |
| `admin.createArticle`, `admin.articleCreationStatus`                          | IndexedDB до POST: исходный payload и lowercase UUID v4 на аккаунт. После timeout/reload сначала status; явный повтор с прежним ключом. `deleted` и `CONFLICT` не создают замену. Отмена перечитывает список; `updateArticle` сохраняет прежний путь без replay.                   |
| `club.createNormalCheckout`, `club.normalCheckoutStatus`                      | Только авторизованный NORMAL и разрешённая сборка. Исходный ключ, план и orderId изолированы по аккаунту; Web Locks защищают запись. Только `succeeded` этой операции подтверждает покупку, доступ проверяется отдельным subscription-чтением. Нет обхода 409/412 старым checkout. |
| `videos.catalog`, `videos.playback`                                           | Каталог без источников, пагинация и устранение дублей. Playback проверяется отдельно, источник закрывается при отказе, уходе страницы, отзыве сессии и смене аккаунта. Public/club, VK/YouTube; для club YouTube нет анонимного worker fallback.                                   |
| `admin.upsertVkVideo`                                                         | Переиспользован VK-ввод с проверкой согласованного HTTPS embed. Явное редактирование по существующему ID; неизвестный результат допускает явный повтор точного payload. Нет преобразования YouTube или обхода CONFLICT/412.                                                        |
| REST register / password request / login; серверная password complete page    | После 202 остаётся инструкция и путь повтора; доставка не объявляется подтверждённой. После password complete нужен отдельный login. Исходный HTML/script серверной страницы проверен с подставным HTTP, контроллер не запускался.                                                 |
| `feed.getById`, `feed.userInteractions`, `feed.toggleLike`, `feed.toggleSave` | Штатное отсутствие и 401/403/404 скрывают старый пост и медиа. Возврат/refetch перечитывает пост и отметки. Неизвестный toggle не повторяется автоматически.                                                                                                                       |
| `club.comments` и существующие действия комментариев                          | Вход требуется для public feed/both, оплата не требуется. Club проверяется сервером. При отказе скрываются старые данные и сбрасываются локальные формы/фото.                                                                                                                      |
| `club.cancel`, `admin.uploadMedia`, существующие create/update постов         | Сохранены подтверждение отмены и свежее чтение срока. Используются серверные url/mimeType/fileSize; upload отдельно не объявляется связью с постом, незавершённые загрузки блокируют частичное сохранение.                                                                         |

Гостевой checkout, TEST и прежние видео остаются на своих путях. Новые сборочные флаги по умолчанию `false`:

- `NEXT_PUBLIC_NORMAL_CHECKOUT_RECOVERY_ENABLED` — включать после схемы `0030` и разрешения серверного `NORMAL_CHECKOUT_RECOVERY_ENABLED`.
- `NEXT_PUBLIC_VK_CATALOG_ENABLED` — включать после схемы `0031` и разрешения серверного `VK_CATALOG_ENABLED`.

Изменение runtime env не переключает уже собранный фронтенд. Для статьи с ключом до POST на стенде необходимо подтверждение схемы `0029`. Наличие SQL-файлов в репозитории не подтверждает применение миграций.

Общий сценарий: первый ответ покупки потерян, reload восстанавливает исходный заказ без второго POST; `succeeded` и отдельное чтение доступа открывают клуб, профиль и VK playback. Отзыв сессии закрывает источник. Новый неоплаченный модератор получает служебный доступ, без отмены оплаченной подписки и без состояния покупки предыдущего аккаунта.

Playwright использует локальный HTTP Next, настоящий браузер, IndexedDB/localStorage и клиентские timeout, но API, платёжная навигация и внешние embed подставные. Это не запуск backend HTTP/cookie/JWT/SQL/SMTP и не проверка настоящего провайдера. Opt-in реальные проверки выключены.

Для повторения из корня репозитория:

```sh
pnpm check:api
pnpm --filter @daryadarcy/frontend typecheck
pnpm lint
pnpm check:boundaries
pnpm check:docs

NEXT_PUBLIC_NORMAL_CHECKOUT_RECOVERY_ENABLED=true \
NEXT_PUBLIC_VK_CATALOG_ENABLED=true \
NEXT_PUBLIC_CLUB_TEST_CHECKOUT=false NEXT_PUBLIC_PRODAMUS_TEST_ENABLED=false \
pnpm build:frontend

NORMAL_CHECKOUT_UI_ENABLED=true VK_CATALOG_UI_ENABLED=true \
RUN_REAL_API_TESTS=0 PLAYWRIGHT_EXECUTABLE_PATH=/usr/bin/chromium \
pnpm test:frontend handoff-acceptance.spec.ts club-access.spec.ts \
article-creation-recovery.spec.ts normal-checkout-recovery.spec.ts \
video-catalog.spec.ts handoff-existing-flows.spec.ts

pnpm build:frontend
RUN_REAL_API_TESTS=0 PLAYWRIGHT_EXECUTABLE_PATH=/usr/bin/chromium \
pnpm test:frontend club-payment.spec.ts vk-video.spec.ts vk-editor.spec.ts
```

Не запускать frontend typecheck/typegen одновременно с build: оба используют `.next`. Browser-прогоны запускаются после завершения соответствующей сборки.
