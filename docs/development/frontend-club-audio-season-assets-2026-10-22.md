# Клуб: старые подкасты и оформление — фронтендеру

22 октября 2026. Фронтенд в этой работе не изменялся. Ни новый плеер,
ни переработка дизайна для серверного исправления не требуются.

## Подкасты: что исправлено на сервере

Три перенесённых вложения `post_media` 13/17/18, посты826/931/932:
исходные `.m4a` содержали ALAC, но были помечены `audio/mpeg`.
Chromium отвергает эти файлы даже после исправления MIME. Native WebKit
в локальном тесте исходники воспроизводит: приписывать конкретный отказ
iPhone только ALAC или только MIME нельзя.

Подготовлены отдельные AAC-LC/faststart копии; исходники не перезаписывались.
Привязки переведены на существующий защищённый API:
`/api/media/post-attachments/13`, `/17`, `/18` (полный префикс одинаковый).
Ответ — `audio/mp4`, HEAD200, GET Range206, `Accept-Ranges: bytes`,
`Cache-Control: private, no-store`. Гость/неоплаченный пользователь получают404;
новые S3-объекты по прямым ссылкам без авторизации получают403.

Использовать `media.url` из API как есть. Не восстанавливать старую прямую
S3-ссылку по имени файла, не определять формат по `.m4a`, не устанавливать
`crossOrigin="anonymous"` для защищённого same-origin источника: нужна сессия.
Текущий `BrowserAudioPlayer` уже использует возвращённый URL непосредственно.
После обновления данных повторить запуск/паузу/продолжение на реальном iPhone.
Кнопки декоративной waveform не превращать в новую функцию в рамках этой задачи.

Локально проверены реальные файлы через настоящий HTTP в Chromium/WebKit:
воспроизведение без mute, прогресс, перемотка70%, пауза/продолжение. Это не
означает физическое прослушивание звука или приёмку на iPhone. Фоновая музыка
Клуба — отдельный источник, не эти три подкаста.

На опубликованном стенде Chromium также прошёл все3 карточки: запуск,
прогресс, перемотка70%, пауза/продолжение. Live WebKit harness зависал;
локальный WebKit не выдаётся за завершённую проверку Safari/iPhone на стенде.

## Оформление: причина ошибки

В revision3 зимнего оформления были сохранены:

- Баннер: `https://disk.yandex.ru/i/iXiEA9lCjqzCkA`.
- Фон: `https://disk.yandex.ru/i/YywN9wfcta05-w`.

Это страницы общего доступа, не адреса изображений. Баннерная ссылка в
проверке перенаправила на `showcaptcha`; `<img>`/CSS background не может
показать HTML как картинку. Видимый клетчатый фон мог быть встроенным fallback,
а не подтверждением загрузки указанного файла. PNG поддерживается; исходный
баннер существует,8 896 834bytes,3640×2316 с прозрачностью.

Подготовлены копии тех же материалов без изменения композиции: баннер
WebP2560×1629/355 766bytes с alpha, фон1200×1200/378 398bytes.
Оригиналы Яндекс Диска и старые S3-файлы остаются на месте. Прямые ссылки
должны приходить из `/api/launch-config`; не хардкодить их в компоненте.
Настройки уже применены: revision4, только две ссылки winter изменены.
23октября настоящий `/club` в Chromium показал новый баннер; обе картинки
декодируются, сообщение ошибки отсутствует. Остальные сезоны, контакт
менеджера и админские входы сохранены. Receipts — в runbook ниже.

## Минимальные правки фронтендеру, без изменения дизайна

1. В полях «Фон/баннер, HTTPS-ссылка» пояснить: нужна **прямая ссылка на
   изображение**, а не страница Яндекс Диска. Известные share-page URL
   отклонять до отправки. Это клиентская помощь, серверная проверка обязательна.
2. Показывать безопасное поле `error` ответа400 при сохранении настроек.
   Backend подготовил явное сообщение о прямой ссылке; прочие внутренние
   ошибки не раскрываются. Эта серверная валидация пока локальная, не выпущена.
3. Для загрузки публичной обложки использовать существующий
   `admin.uploadPhoto` с явным `purpose:"publicCover"`; передавать реальный
   файл JPEG/PNG/WebP до4МиБ, а в настройки сохранять возвращённый `url`.
   Исходный8,9МБ PNG превышает этот действующий контракт. Не повышать квоту
   и не отправлять его Base64 вслепую; тяжёлые загрузки на текущем API
   требуют отдельной проверки памяти. Автоматический импорт Яндекс Диска
   в runtime не добавлялся.
4. После успешного сохранения обновить общий query оформления; при отказе
   оставлять старое оформление и доступный повтор. Не заменять ошибку
   успешным пустым ответом и не стирать остальные сезоны/контакт менеджера.

В ходе браузерной проверки карточки установки приложения перехватывали
нажатия по плееру. Для теста закрывать карточку штатной кнопкой «Понятно →»;
backdrop-кнопка «Закрыть» может перекрываться содержимым карточки. Это
наблюдение для отдельной проверки, не причина кодека и не правка дизайна здесь.
