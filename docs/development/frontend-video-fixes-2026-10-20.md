# Фронтендеру подключение каталога и плеера VK

Дата: 20 октября 2026 года. Стенд: <https://daryadarcy.dev.reeskeen.ru/videos>.

Нужно подключить проверенный локальный backend-контракт обложек к существующим карточкам и использовать уже реализованную VK-ветку плеера. Дизайн, размеры карточек, цвета и навигацию не менять. Backend-изменения ещё не выложены; этот документ не означает готовность опубликованного раздела.

[Серверный контракт и результаты проверок](backend-video-fixes-2026-10-20.md).

Backend-коммиты для интеграции: `36fc86d` (чтение обложек по opt-in) и `b6dbdf4` (сохранение обложки VK и replay). Они сохранены только локально в рабочей ветке; публикация в staging не выполнялась.

## Что уже подготовлено и что остаётся

- Backend выдаёт обложки по явному запросу клиента и принимает их при сохранении VK-записи. Старый клиент продолжает получать прежний ответ.
- Повторы создания, обрыв HTTP-ответа после записи, конкурентные запросы и права проверены локально на одноразовой SQL-БД. Это не проверка внешнего VK-плеера.
- Получен настоящий экспорт видео «Путешествие по Англии»: host `vk.ru`, `oid=-211171256`, `id=456239238`. Полный `src` с hash брать из сообщения владельца, не из Git.
- Рабочий каталог не менялся. Старые YouTube-записи сами не превратились в VK-записи; один экспорт не является заменой всему каталогу.
- У инструмента браузерная проверка VK заблокирована site-safety policy. Реальное воспроизведение остаётся на совместную ручную приёмку. Это не ошибка, возвращённая VK.

На опубликованной странице коричневые карточки возникают потому, что `VideoCatalogScreen` не отрисовывает изображение. Простое включение серверного флага или замена видеохостинга обложку не добавит.

## 1 Обновить клиентский контракт

После получения backend-коммитов выполнить штатную генерацию `pnpm api:contract`, затем `pnpm check:api`. Backend-исполнитель файл `apps/frontend/src/shared/api/contract.ts` не менял по запрету на правки фронта.

В строгую схему карточки добавить `thumbnailUrl: string | null | undefined`. Остальные проверки сохранить. Не заменять валидацию на произвольный объект.

Запрос каталога:

```ts
videos.catalog.query({
  limit: 20,
  includeThumbnails: true,
  // cursor: nextCursor, // только для следующей страницы
});
```

Поле карточки при этом запросе:

```ts
{
  id: number;
  title: string;
  duration: string | null;
  access: "public" | "club";
  canWatch: boolean;
  thumbnailUrl: string | null;
}
```

Без `includeThumbnails` и с `false` поля `thumbnailUrl` в ответе нет. Это штатная совместимость со старым API-клиентом, а не ошибка.

Передавать параметр и на первой, и на следующих страницах; учитывать его в ключе запроса. Сохранить пагинацию, дедупликацию по ID, защиту от повторного курсора и обработку ошибки следующей страницы. Не выполнять playback или отдельный запрос деталей для каждой карточки.

## 2 Показать обложку в существующей карточке

- Использовать принятый в проекте компонент изображения внутри текущего `thumbnailContainer`.
- Сохранить соотношение сторон, скругления, положение Play или замка и длительности.
- При `null`, отсутствующем поле или ошибке изображения показывать резервное состояние в тех же размерах. Не оставлять бесконечную загрузку.
- Не строить превью из адреса видео, iframe, VK hash или закрытого файла. Каталог возвращает только метаданные; наличие обложки не даёт права просмотра.

Backend сейчас допускает существующие изображения в `/assets/responsive/` и HTTPS S3 `daryadarcy-s3/feed/` либо `app-assets/`, без query, fragment и credentials. Произвольные VK CDN URL, подписанные адреса и закрытые префиксы автоматически не принимаются. Проверка адреса не доказывает наличие файла или пригодность картинки: для обложки нужен реально согласованный публичный файл.

Это не новый API загрузки обложек. Если подходящего публичного адреса нет, оставить `null` и передать список на наполнение; не открывать для этого приватное хранилище.

## 3 Сохранять обложку через существующий VK endpoint

Контракт `admin.upsertVkVideo`:

| Поле | Значение |
|---|---|
| `embedUrl` | HTTPS `src` из экспорта `video_ext.php`, до 2048 символов |
| `title` | Название, от 1 до 512 символов после trim |
| `access` | `public` или `club` |
| `published` | boolean |
| `id` | Необязательный ID существующей VK-записи для обновления |
| `thumbnailUrl` | Необязательный безопасный публичный адрес или `null` |

Успешный ответ — `{ id: number }`. Отсутствующий ID в запросе означает создание с дедупликацией по VK `oid/id`, а не безусловное создание новой строки.

Семантика обложки:

- При создании отсутствие поля или `null` означает отсутствие обложки.
- При обновлении отсутствие поля сохраняет прежнюю обложку.
- Явный `null` при обновлении удаляет только привязку обложки.
- Строка сохраняет нормализованный адрес. Пустая строка и запрещённый адрес дают 400, а не молчаливое удаление.
- Если поле формы не менялось, не посылать `null` автоматически. Если пользователь явно очистил поле, отправить `null`.

После потери ответа повторять тот же create payload. Не менять URL, title, access, published или обложку в автоматическом повторе. Тот же источник с другим содержимым даёт 409; это не разрешение создавать дубликат или затирать сохранённое. Для намеренного редактирования использовать возвращённый ID.

`id` не превращает старую YouTube-запись в VK: endpoint обновляет только существующие VK-записи. Сопоставление старого каталога с новыми экспортами и изменение рабочих публикаций согласовываются отдельно.

## 4 Использовать текущий VK плеер

В проекте уже есть `CatalogVideoDetail`, `videos.playback` и `VkVideoEmbed`. Подключить их, не создавать второй плеер и не вставлять произвольный HTML.

- В запрос сохранения передавать только `src`, не весь iframe. `wall-...` и `VK.Widgets.Post` — не видеоплеер.
- Получать источник через `videos.playback({ id })`. При `provider: "vk"` использовать проверенный `embedUrl` в существующем компоненте.
- Не использовать YouTube ID, `/api/yt/` или YouTube-обложку для VK-записи.
- Не получать hash самостоятельно, не исполнять присланный script и не включать autoplay.
- Не переносить в VK подсказку с обещанием «работает без VPN». Сохранять нейтральное сообщение о плеере VK.

В каталоге нет адреса воспроизведения. Доступ к клубному ролику проверяет сервер при playback; `canWatch` — только состояние карточки. При уходе со страницы, выходе и смене аккаунта старый iframe должен прекращать воспроизведение; возвращение не должно обходить новую проверку доступа. После отзыва доступа следующий playback должен получить отказ, без возврата старого iframe из кэша. Мгновенный отзыв уже выданной внешней ссылки или отдельный сервис постоянного опроса в это задание не входят.

Не обещать DRM или защиту самого VK-ролика: по согласованному объёму клубные видео размещаются в VK без такой защиты. В приложении сохраняется проверка доступа.

## 5 Ошибки и повтор

| Ответ playback | Действие клиента |
|---|---|
| 401 | Предложить вход; не подставлять старый источник |
| 403 | Показать требование клубного доступа |
| 404 | Сообщить, что запись не найдена или не опубликована |
| 412 | Показать недоступность каталога; проверить согласованные настройки |
| 5xx или сеть | Ошибка с повтором, без вывода о выходе из аккаунта |

Для ошибок сохранения: 400 — исправить ввод; 409 — конфликт с существующей записью; 403 — недостаточно прав; 404 при обновлении — подходящей VK-записи нет.

Не заменять отказ API прямой внешней ссылкой клубного ролика. Не бесконечно повторять запросы и не продолжать использовать источник от предыдущего аккаунта.

## 6 Порядок интеграции и приёмка

1. Получить backend-изменения, обновить generated contract и схему карточки.
2. Подключить опцию обложек и поле сохранения в существующей логике без редизайна.
3. Проверить локально на одноразовой БД; реальный каталог и S3 не менять.
4. Отдельно согласовать список VK-источников, публичные обложки и сопоставление со старыми карточками.
5. Публикацию и изменение рабочих данных выполнять только после отдельного разрешения.
6. После согласованного выпуска проверить реальный плеер в обычном браузере.

Чек-лист:

- [ ] Обложка отображается; `null`, отсутствующий адрес и ошибка картинки не ломают карточку.
- [ ] Первая и следующие страницы используют один согласованный контракт, без дублей.
- [ ] Сохранение, повтор после потери ответа, 409 и явное удаление обложки обработаны правильно.
- [ ] Открытый VK-ролик играет не менее 60 секунд, поддерживает паузу, продолжение, перемотку и полноэкранный режим.
- [ ] Гость и обычный пользователь без клубного доступа не получают клубный источник; участница и служебные роли сохраняют согласованные права.
- [ ] Смена аккаунта и уход со страницы прекращают старое воспроизведение. После отзыва доступа повторное открытие или возвращение не восстанавливают источник из кэша.
- [ ] Ошибка VK видна пользователю и не заменяется зависшим пустым экраном.
- [ ] Нет изменений дизайна, автоматической массовой замены каталога или открытия приватных файлов.

60 секунд — минимальный предлагаемый сценарий проверки, не новое договорное SLA. Для приёмки приложить снимок карточек, браузер/версию выпуска и результаты сценариев. Краткий старт или наличие метаданных не означают успешного воспроизведения.
