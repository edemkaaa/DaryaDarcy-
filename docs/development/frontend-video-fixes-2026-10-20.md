# Задачи фронтендеру по обложкам и плееру видео

Дата: 20 октября 2026 года. Стенд: <https://daryadarcy.dev.reeskeen.ru/videos>.

Нужно подключить обложки к существующим карточкам и проверить обработку ошибок плеера совместно с бэкендом. Дизайн, размеры карточек, цвета, навигацию и оформление раздела сохранить. Коричневые прямоугольники сейчас возникают потому, что в режиме нового каталога изображение вообще не отрисовывается.

Связанное задание: [задачи бэкенду](backend-video-fixes-2026-10-20.md).

## Последнее уточнение для интеграции

Пользователь подтвердил VK вместо YouTube. Работать с существующей VK-веткой; не заменять весь каталог одним постом. Присланный `VK.Widgets.Post` встраивает публикацию, а не видеоплеер. Для живой проверки ожидается экспорт `video_ext.php` из меню самого видео. YouTube-сценарии ниже остаются историей прежнего сбоя, не задачей по развитию YouTube-прокси.

Backend локально реализовал `videos.catalog({ limit: 20, includeThumbnails: true })`. Только при явном `true` карточки содержат `thumbnailUrl: string | null`; без параметра и с `false` форма ответа прежняя. Параметр нужен и на первой, и на следующих страницах. Добавить его в ключ запроса, чтобы не смешивать формы ответа. Изменения не опубликованы; реальные VK-записи и обложки автоматически не импортированы.

Локальная реализация возвращает существующие `/assets/responsive/` и HTTPS S3 `daryadarcy-s3/feed/` либо `app-assets/`, без параметров и фрагментов. Подписанные URL, адрес плеера и произвольные VK CDN URL дают `null`. Если подходящей обложки нет, передать список на наполнение, а не извлекать закрытый источник.

## Что подтверждено

В `VideoCatalogScreen` блок превью содержит коричневый фон, значок Play или замок и длительность. Компонента изображения в нём нет. Данные каталога также не содержат поля обложки. Это совместный пробел интеграции, а не подтверждённая ошибка скачивания изображений и не основание относить всю проблему к фронтендеру.

Первый ролик `/video/1` в браузерной проверке использовал `/api/yt/sq7pY1H_fYU`. После краткого старта появилась ошибка воспроизведения; повторная загрузка при последнем наблюдении оставалась в буферизации. Конкретная причина пока не установлена. Это не проверка VK-плеера и не доказательство, что ошибку вызывает фронтенд.

## F1 Подключить обложки без изменения дизайна

1. Добавить в клиентскую схему карточки `thumbnailUrl: string | null | undefined`, сохранив строгую проверку других полей. Отсутствие поля совместимо со старым API, `null` означает отсутствие подходящего публичного адреса.
2. Обновить generated contract штатной командой `pnpm api:contract` после получения backend-изменений. Затем включить `includeThumbnails: true` в запросах. Не отключать всю проверку ответа ради одного поля. Серверный тест совместимости со старой формой уже проходит локально.
3. Отрисовать обложку в существующем `thumbnailContainer` через принятый в проекте компонент изображения. Сохранить соотношение сторон, скругления, Play или замок, длительность и кликабельность всей карточки.
4. При отсутствии адреса или ошибке изображения показывать предусмотренное резервное состояние в тех же размерах. Не оставлять бесконечную загрузку; не показывать сломанный значок изображения. Постоянный коричневый фон не должен заменять существующую доступную обложку.
5. Не получать обложку через `videos.playback`, не загружать видео ради превью и не делать отдельный запрос деталей для каждой карточки. Проверка доступа и получение источника остаются на странице ролика.

Не возвращать старый публичный список вместо защищённого каталога для обхода проблемы. Не извлекать ссылку на клубный файл или VK hash для построения превью. Использовать только согласованную публичную обложку из API.

## F2 Собрать точную диагностику ошибки плеера

Для `/video/1` записать последовательность действий, браузер и время проверки. В момент отказа зафиксировать:

- события `loadedmetadata`, `playing`, `waiting`, `stalled`, `error` и момент изменения источника;
- `MediaError.code` и сообщение непосредственно в обработчике события, `readyState`, `networkState`, `currentTime`;
- статус и заголовки проблемного медиазапроса, загрузку диапазонов и отменённые запросы;
- переходы между страницами, скрытие вкладки и повторное монтирование компонента, если они произошли.

Секреты, cookies и подписанные URL в общий отчёт не включать. Позднее чтение `video.error === null` не доказывает отсутствия ранее возникшей ошибки.

В `ManagedVideo` уже есть сообщение об ошибке и кнопка повтора. Не добавлять их заново. Проверить, что повтор действительно загружает актуальный разрешённый источник, снимает старое состояние ошибки и не попадает в цикл. Любую найденную ошибку жизненного цикла сначала воспроизвести тестом, затем исправлять локально. Не считать обычную паузу при скрытии вкладки сбоем сервера.

Для клубного ролика повтор, возвращение на страницу и смена аккаунта не должны восстанавливать старый источник без проверки доступа. Не обходить серверные отказы через legacy API или прямую ссылку провайдера.

## F3 Уточнить сообщение о доступности видео

YouTube-ветка показывает безусловное сообщение «В приложении видео доступно к просмотру без VPN». Не переносить его в VK-ветку: использовать сообщение о плеере VK без обещаний доступности в любой сети. Если старые YouTube-записи временно остаются, убрать для них абсолютную гарантию, сохранив место и оформление подсказки.

Для VK и других источников сохранять соответствующие им элементы управления и сообщения. Не выдавать YouTube-прокси за VK-плеер. Не показывать гостю внешнюю ссылку клубного видео в качестве обхода отказа API.

## F4 Проверка результата

Минимальный предлагаемый набор проверок, без расширения функций:

- [ ] Карточка с валидной обложкой показывает изображение; размеры и дизайн не изменились.
- [ ] Отсутствующая обложка, `null`, ошибка её загрузки и старая версия API не ломают каталог.
- [ ] Следующая страница не теряет обложки, не дублирует карточки и не вызывает запросов playback для списка.
- [ ] Первый проблемный и второй открытый ролик воспроизводятся не менее 60 секунд, поддерживают паузу, продолжение и перемотку. Краткий старт не считается приёмкой.
- [ ] Ошибка источника видима пользователю; повтор проверен после восстановления сервера. Нет бесконечной загрузки или оставшегося сообщения после успешного повтора.
- [ ] Уход со страницы останавливает ролик. Возвращение и смена аккаунта не продолжают клубное видео из старого состояния.
- [ ] Правила для гостя, участницы и администратора сохранены; отказ доступа не маскируется как ошибка сети.

В отчёте приложить снимок карточек, результат воспроизведения и обезличенную сетевую диагностику. Если медиазапрос падает на сервере, передать его бэкендеру; не подменять устранение причины внешней кнопкой.

## Границы задания

Не менять дизайн, правила подписки, рабочую БД, старые файлы и S3. Не добавлять автозапуск или новый видеохостинг. Сначала выпустить совместимость контракта согласованно с бэкендом; публикация изменений требует отдельного разрешения. Это задание по обнаруженной проблеме видео, не повторный аудит всего приложения.
