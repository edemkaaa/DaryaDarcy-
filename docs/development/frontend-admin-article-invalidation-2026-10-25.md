# Фронтендеру: обновление админских данных после сохранения статьи

## Подтверждено на стенде

Проверка25октября, web014a780/BUILD_ID xoiuyRUQ1qHuIKHPy7_v7, только временная
статья7 и анонс951. Публикация, редактирование и снятие статьи с публикации
сохраняются правильно. Но верхние счётчики админки остаются прежними до reload.

Воспроизведение: создать черновик статьи → опубликовать → изменить заголовок →
вернуть в черновик → открыть «Посты». Анонса уже нет, но верхний блок показывает
934/930 вместо фактических933/929. После обновления страницы счётчики верные.
Временные данные после проверки удалены; использовать новые синтетические.

## Минимальная правка

В apps/frontend/src/features/admin/articles-admin.tsx после подтверждённого
create/recovery, update и delete обновлять также связанные админские запросы:

- admin.postsPage;
- admin.postCounts;
- admin.postCalendar;
- admin.stats.

Сохранить существующие обновления articles.* / club.list и защиту текущего
аккаунта/операции. Можно переиспользовать небольшой общий callback по аналогии
с invalidatePublicFeeds в admin-screen.tsx. Полное перечитывание всех постов,
новый API, миграция или изменение дизайна не нужны.

Причина: сервер атомарно синхронизирует анонс source=article:<id> в posts.
Публикация создаёт его, редактирование обновляет, черновик/удаление убирает.
Только обновления списка статей недостаточно для зависимых представлений.

## Проверить

- После create published / draft→published счётчики и клубный анонс обновляются
  без reload; только одна статья и один анонс.
- После изменения заголовка он актуален в статье, списке постов и календаре.
- После published→draft и delete анонс исчезает, счётчики уменьшаются без reload.
- Ошибка записи не выглядит успешным обновлением; смена аккаунта не переносит
  локальное состояние и поздний ответ в другой профиль.
- Не возвращать legacy admin.posts и не сбрасывать без причины все страницы.

Бэкенд и production frontend в рамках этой проверки не менялись.
Отдельно остаётся повтор живого удаления кнопками: native confirm заблокировал
инструмент проверки; дефект обработчика удаления этим не доказан.
