## Одна команда для запуска у владельца

Открой Терминал и вставь целиком:

```sh
pnpm --dir "/Users/edem/Desktop/ASSIST/dina_project/daryadarcy-app" exec tsx tooling/data/collect-vk-oembed.ts --input "/Users/edem/Downloads/daryadarcy-vk-video-links-2026-10-20.txt" --output "/Users/edem/Downloads/daryadarcy-vk-metadata-2026-10-20-v2.json" --collect
```

После завершения пришли файл `daryadarcy-vk-metadata-2026-10-20-v2.json` из Downloads
в этот чат. Его не нужно загружать на сайт, в S3 или коммитить в Git.
Новый суффикс `-v2` сохраняет первый частичный отчёт, не перезаписывая его.

Команда отправляет последовательные запросы только к фиксированному VK API,
без авторизации; между роликами пауза400мс, таймаут каждого запроса10секунд,
без автоматических повторов. Если сеть медленная, завершение займёт дольше.
Утилита не читает настройки аккаунта и не обращается к рабочему приложению.

Для безопасной проверки списка **без сети** есть режим:


## Как понять результат

В конце терминал покажет количество `ok`, `incomplete`, `failed`, но не выведет
сами iframe/hash. Код завершения0 означает, что все ответы содержат нужные
метаданные;2 — есть частичные ответы или отказы, но JSON-отчёт сохранён.
Код1 означает ошибку запуска, входного файла или сохранения.

В JSON у каждого ролика будут:

- `sourceUrl`: исходная страница ролика;
- `title`: заголовок от API либо null;
- `embedUrl`: проверенный matching src плеера либо null;
- `thumbnailSourceUrl`: HTTPS-адрес обложки либо null;
- `status` и `issues`: результат и безопасные коды ошибок.

`ok` означает только сбор метаданных, **не успешное воспроизведение**. Во всех
отчётах playbackVerified=false, importReady=false, thumbnailBytesDownloaded=false.
Общие ответы API, сторонний HTML/scripts и тексты ошибок в файл не переносятся.
Iframe oid/id обязан совпасть с исходным роликом; используется существующий
серверный валидатор и autoplay0 после удаления только известного oEmbed tracking
параметра. Hash/oid/id не придумываются и не заменяются. Встраивание не
предполагается по одному ID.

## Если есть ошибки

- `EEXIST`: выбранный JSON уже существует. Он не перезаписан; для нового
  запуска поменяй имя после `--output`, например добавь `-v2`.
- `vk_error_...` или `http_...`: официальный API отказал. Пришли имеющийся отчёт;
  не добывай токены через чужие сервисы и не отправляй пароль/cookies.
- `request_timeout/request_failed`: сеть или запрос не завершились; причина
  доступа к ролику этим не установлена. Отчёт остальных роликов сохраняется.
- `invalid_embed`: API не дал подходящий подтверждённый iframe для этого ролика;
  его не подменяют ссылкой на страницу или плеером другого видео.
- `missing_or_invalid_thumbnail`: обложка отсутствует либо адрес не подходит.
  Пустое значение не маскируется выдуманной картинкой.
- `invalid_response`: ответ не прошёл схему/JSON/размер64КиБ. Повторять без
  выяснения причины автоматически не нужно.

Новый output создаётся с правами0600; существующий файл или symlink не
перезаписывается. Сохранение внутри репозитория запрещено до сетевых запросов.
JSON содержит полные адреса плееров: держать его вне Git и публичной раздачи.
При прерывании/ошибке записи файл может остаться незавершённым; наличие файла
без корректного JSON не означает успешный сбор. Не перезаписывать его вслепую.

## Что будет после получения JSON

2. Отдельно принять воспроизведение реальных роликов и согласовать public/club.

4. Только по отдельному согласованию наполнить рабочий каталог и выпустить
   вместе с [правками фронтендера](frontend-video-fixes-2026-10-20.md).

Утилита не скачивает видеопотоки/обложки, не импортирует записи, не удаляет
старые материалы и не гарантирует DRM или доступность VK на каждом устройстве.
