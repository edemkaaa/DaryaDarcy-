# Фронтендеру: правки по аудиту be029ed

Дата: 23 октября 2026. Исходники фронта в ходе backend-работы не менялись.
Источник — три переданных отчёта от23октября; ниже только подтверждённые
пункты и необходимые изменения, без редизайна и новых функций.

## INT-01: размер batch — исправить на клиенте

В `shared/api/trpc.ts` задать `httpBatchLink` предел `maxItems:20`.
Сервер намеренно отклоняет больше20 операций до их выполнения; повышать
или убирать этот предел нельзя. Мутации с ключами операций оставить на
отдельном `httpLink`, не упаковывать их с разными ключами в один batch.

Проверка:20/21/40/41 одновременных чтений успешно разбиваются на допустимые
пакеты, ни один HTTP-запрос не содержит больше20 имён. Использовать здоровый
синтетический API/БД либо чтение без зависимости от БД. `feed.tags` при
отсутствующей БД теперь корректно возвращает503, а не пустой успешный список.

## FE-01: защита Клуба остаётся в скрытой вкладке

`ClubSubscribed` вызывает `useClubContentProtection(true)`, но сохранённые
вкладки остаются смонтированными. Привязать эффект к активности экрана и
нужному контейнеру; если общие обработчики сохраняются — учитывать владельцев.
Не превращать защиту от копирования в обещание защиты файла по прямому URL.

Проверка: магазин→Клуб→магазин/профиль/правовые страницы; копирование вне
Клуба не блокируется. Переход в закрытую статью/назад не ломает владение эффектом.

## FE-04: нижнее меню при продлении

`tab-shell.tsx` скрывает общее меню по `/club + hasClubAccess`, а checkout
показывает лендинг вместо `ClubSubscribed` с клубным меню. Выбирать меню
по реально отображённому состоянию, включая `forceCheckout`.

Проверка: активная подписка→профиль→продлить; reload/back/выход в ленту;
обычный вход в Клуб. Нельзя оставлять оба меню скрытыми или показывать два.

## FE-05: cropper — ограниченное ожидание и честная ошибка

`canvas-image.ts` ждёт Image.onload без deadline/отмены;
`avatar-cropper.tsx` при ошибке вызывает `onCrop(imageUri)` и принимает исходник.
Использовать существующий `runFileTask`, отменять при закрытии/смене владельца,
не выдавать исходник за успешно обрезанное фото. Показать ошибку и позволить
повторить с сохранённым выбранным изображением; освобождать локальные ресурсы.

Проверка: зависшее/повреждённое изображение, закрытие в обработке, повтор,
смена аккаунта; выбранная область не меняется молча. Дизайн не менять.

## FE-06: поздний redirect NORMAL checkout

`use-normal-club-payment.ts` должен терять право на внешний переход уже при
начале ухода из checkout, не только после подтверждения нового pathname.
Сохранённый purchase intent при этом не удалять и новую оплату не создавать.

Проверка: удержать ответ создания покупки, нажать «Лента», отпустить ответ;
оставаться в ленте. Повторный вход/back/account switch/recovery сохраняют
тот же intent. Проверять отдельной NORMAL-сборкой: Prodamus TEST имеет приоритет
и не доказывает исправность NORMAL. Реальный платёж для теста не нужен.

## FE-02 / INT-05: фильтры и глубокое обновление

Не прекращать дозагрузку вслепую: иначе спрячутся реальные совпадения.
Требуется согласованный серверный фильтр рубрик/алиасов, его включение в query
key и отдельная политика обновления глубоко загруженных страниц. Текущий
backend `tag` — один точный тег, не готовый контракт рубрик с алиасами.
Изменение wire-контракта ещё не внедрено; полный архив не обрезать скрытым cap.

Проверка: редкая/пустая рубрика, смена фильтра, конец выдачи/повтор cursor,
обновление при60 загруженных элементах без повторного чтения всего архива.

## FE-03 / INT-04: клубные иллюстрации — совместный перенос

Исследование подтвердило220 иллюстраций клубного дополнения, а не домиков
бесплатного результата. Подробные источники, варианты и границы —
[отдельная проверка назначения](../audits/aesthetic-visual-access-2026-10-23.md).
Не удалять public-файлы до готовности привязок и подключения обоих клиентов.
Не считать подготовленный план уже выложенным защищённым API.

## FE-07 и INT-03: точечные согласования

- `/privacy.html` и `/privacy` имеют разные контакты. Привести к согласованному
  `PUBLIC_CONTACT_EMAIL`, не создавать третью копию документа.
- В форме сезонов пояснить требование прямого изображения и заранее
  отклонять известные share-page URL Яндекс Диска. Не обходить серверную
  проверку и не добавлять произвольный server fetch.
- Для полного отображения нового зимнего баннера остаётся
  [узкая инструкция](frontend-winter-banner-fit-2026-10-23.md).

## Что меняется на бэке локально

Схемы успешных ответов и90 wire-процедур сохранены. У отсутствующей БД
каталоги/детали/комментарии больше не выглядят подтверждённо пустыми:503.
Модератор получает403 при попытке изменить staff или себя. Публичная storage
запись ограничена10s и отменяется при разрыве HTTP-запроса, SDK не повторяет
PUT автоматически. Это **не** новый recovery-контракт аватара/обложки: потеря
ответа всё ещё может означать неопределённый результат записи объекта.
Не добавлять автоматический повтор POST и не сообщать «файл точно не сохранён».

Исправления бэка пока локальные, не считать их уже доступными на стенде.
