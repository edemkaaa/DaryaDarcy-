# Сжатие публичных ответов API

26 октября 2026. Локальная реализация, без изменения процедур и формата JSON.

Для анонимных `GET /api/trpc/…` используется стандартный Express middleware
`compression` (зафиксированная production-зависимость). Разрешены только
`feed.listPaginated`, `feed.getById`, `feed.tags`, `videos.catalog`, `articles.list`.
В пакете должны быть только разрешённые процедуры, максимум 20.

Ответ должен иметь статус 200, тип `application/json` и размер от 1024 байт.
Клиент договаривается о gzip/Brotli через `Accept-Encoding`; добавляется
`Vary: Accept-Encoding`. Уровень gzip 4, качество Brotli 4. Распакованный ответ
совпадает с исходными байтами. Форматы и качество фотографий не меняются.

Сжатие запрещено при любом Cookie/Authorization, Range/If-Range, Set-Cookie,
`Cache-Control: private/no-store`, для ошибок, смешанных пакетов, изменений,
авторизации, закрытых материалов и бинарных файлов. Сохраняется стандартное
правило `no-transform`. Новый публичный кеш не создаётся. Запрет сжатых входящих
запросов (415) остаётся прежним.

Проверка: `tests/public-response-compression.test.ts`, настоящий loopback HTTP,
исходные заголовки/байты, gzip/Brotli и исключения. Внедрение в основной,
TEST и sandbox процесс происходит через общий `registerHttpSecurity`.
Контракт фронтенда не меняется: браузер самостоятельно распаковывает ответ.
У вошедших пользователей этот механизм намеренно не применяется.

Это уменьшение передаваемого JSON, а не доказательство улучшения LCP/INP или
замена измерения на стенде после выпуска. Кеширование фото регулируется отдельно.

Зависимость и правила согласования:
[Express compression](https://github.com/expressjs/compression).
Dockerfile backend устанавливает production workspace dependencies по frozen
lockfile; локальный build сам по себе не является проверкой нового Docker-образа.
