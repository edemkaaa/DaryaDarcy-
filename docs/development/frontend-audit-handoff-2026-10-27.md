## 1. Порядок публикаций Клуба

`club.list` и `club.listByCategory` сортируют весь результат **до пагинации**:
дата публикации, при её отсутствии дата создания, по убыванию; при равных датах
ID по возрастанию. Ручной порядок админки и календаря сохранён.

В `apps/frontend/src/features/club/club-subscribed.tsx` убрать дополнительный
`.sort()` после преобразования постов. Он сортирует только загруженную часть;
локальное поле `createdAt` здесь получено через `postDisplayDate`, это не
доказательство сортировки по сырой дате создания. Прежний серверный ручной
порядок этот шаг переопределял; после backend-исправления он избыточен.
Сохранять порядок страниц API. При выпуске сбросить старую цепочку клубных
страниц/курсоров, чтобы не смешать страницы двух порядков.
Проверить первую и следующие страницы, равные даты, фильтры рубрики/тега,
возврат на экран и смену аккаунта. OFFSET при конкурентных новых публикациях
по-прежнему может смещаться: отсутствие дублей проверять и на стабильном наборе.

## 2. Фоновое обновление длинной Ленты

`feed-screen.tsx` использует `useInfiniteQuery` вместе с минутным
`contentRefreshOptions`. Перечитываются все накопленные страницы; `gcTime`
и виртуализация этого не ограничивают.

Определить ограниченное удержание страниц и фоновое обновление начала/видимой
области с сохранением позиции. Не подменять это постоянным полным сбросом
списка. Проверка: прокрутить пять страниц, выполнить один цикл обновления,
посчитать запросы и убедиться, что экран не прыгает.

## 3. Реакции и лишние инвалидации

В `domain/post/use-post-interactions.ts` после подтверждённого ответа уже
обновляется кеш реакций, но затем инвалидируются сохранённое и целые списки.
Даже лайк затрагивает сохранённые посты.

Разделить последствия лайка и сохранения. Обновлять конкретную карточку,
реакцию и счётчик; перепроверку неопределённого результата запроса сохранить.
Не запускать полное чтение накопленных страниц после каждого лайка.

В `post-interaction-data.ts` неполная группа из максимум 50 ID меняет ключ
при каждой догрузке: 12 → 24 → 36. Использовать стабильные группы страниц
либо хранение реакций по ID с дозагрузкой отсутствующих. Проверить пересечения
одного поста между Лентой, Клубом, деталями и «Сохранённым».

## 4. Обновление второй и следующих страниц

`shared/api/use-cursor-pages.ts` читает при обновлении только голову.
`mergeCursorHead` сохраняет хвост, если ID/курсор первой страницы прежние.
Редактирование или удаление другой админкой на второй странице останется старым.

Явное обновление должно перепроверять видимые страницы или согласованно
перезапускать цепочку. Фоновый режим сделать ограниченным, без бесконечного
хранения устаревшего хвоста. Проверить внешнее редактирование/удаление записи
второй страницы при неизменившейся первой; ошибку следующей страницы и повтор.

## 5. API-типы

Серверные типы больше не теряют фактически выдаваемые поля:

- `feed.getById`: `media`;
- `feed.listPaginated`: `commentCount`;
- `club.list` / `club.listByCategory`: `media` и `commentCount`.

Использовать `ApiOutputs` из сгенерированного контракта, убрать обходные
локальные типы/приведения там, где они компенсировали именно эти пропуски.
SuperJSON передаёт даты как `Date`: не объявлять их строками в модели видео
без отдельного явного преобразования. Новая служебная процедура
`videos.publicYoutubeState` нужна старому видеосервису, экрану VK она не нужна.

## 6. Ограниченные старые методы

Полные совместимые выдачи теперь читают не более 201 строки и при результате
свыше 200 возвращают **413 / PAYLOAD_TOO_LARGE**, без молчаливого обрезания.
Переходы для актуальных экранов:

| Старый вызов | Использовать |
| --- | --- |
| `feed.list` | `feed.listPaginated` |
| `feed.savedPosts` | `feed.savedPostsPage`, отдельно `target: feed/club` |
| `feed.userInteractions` | `feed.interactionsForPosts` для нужных ID |
| `club.comments` | `club.commentsPage` с тем же postId |
| `admin.posts` и старые полные фильтрованные списки | `admin.postsPage` + `admin.postDetail` |
| Старые общие данные календаря | `admin.postCalendar`; счётчики — `admin.postCounts` |
| `admin.members` | `admin.membersPage` |
| `admin.articles` | `admin.articlesPage` + `admin.articleDetail` |

В текущем коде основные экраны уже используют новые методы; оставшиеся
инвалидации старых ключей не равны реальному чтению. Не переписывать готовое:
проверить активные запросы, fallback и старые потребители перед выпуском.

## 7. Видео: занята загрузка

RAW `POST /api/admin/private-video-uploads` допускает одну обрабатываемую
видеозагрузку на процесс, включая её проверку и запись в хранилище.
Следующая получает **429**, `Retry-After: 2`, `Cache-Control: no-store` до
чтения тела. Это не изменение квоты 80 МиБ и не включение отключённых флагов.

Показывать понятное состояние занятости. Повтор — с тем же ключом операции,
без создания нового намерения. При потере ответа сначала проверять статус,
как в существующем протоколе восстановления. Не делать бесконечные автоматические
повторы больших тел. Проверить повтор после 429, ошибку, отмену и смену аккаунта.
HTTP 429 не означает подтверждённого выхода из аккаунта.

## 8. Валидация и старое удаление вложений

`source` ограничен 32 символами; пространство `article:` предназначено
для автоматических анонсов, не для ручного создания поста.
Идентификаторы затронутых старых чтений/записей — положительные целые числа
в безопасном диапазоне. Ошибки ввода возвращаются как 400 до SQL.

`admin.deleteMedia` теперь использует общий путь сохранения: удаление последнего
содержимого отклоняется, операция откатывается целиком. Основной редактор уже
использует `updatePost`; сохранять этот путь. При отказе не убирать вложение
из подтверждённого состояния клиента как будто удаление состоялось.

## 9. Длина GET-пакетов и тесты

В `shared/api/trpc.ts` у `httpBatchLink` есть `maxItems: 20`, но нет
`maxURLLength`; установленный tRPC поддерживает этот параметр. Ограничить длину
с учётом существующего прокси и проверить пакет из 20 запросов реакций по 50 ID:
он должен разделиться, сохранив состав и владельца запросов.

В `e2e/media-upload-contract.spec.ts` подменяется `admin.uploadPhoto`, хотя
актуальная обложка идёт через `admin.uploadPublicCover`. Исправить подмену,
сохранив проверку назначения обложки/ключа/результата. Проверки реакций
синхронизировать с сетевым завершением, а не только с оптимистическим DOM.

## 10. Размеры фото без снижения качества

В текущем `features/admin/admin-screen.tsx` у Picture с классом postThumb нет
sizes, хотя слот56px. Передать `sizes="56px"`; проверить фактически выбранные
ресурсы при DPR1/2/3. Не фиксировать всем посетителям самый маленький источник.

В `features/profile/profile-screen.tsx` у savedPostImage также нет sizes;
согласовать его с существующим слотом около31% контейнера и мобильной раскладкой.
В `domain/content/article-content.tsx` проверить carousel и его58vw. Дизайн,
quality и отдельный крупный viewer не менять, закрытые URL не передавать
публичному optimizer. Порядок srcSet/src для Safari уже исправлялся: сохранить,
а не повторять прежнюю правку вслепую.

На измеренном исходнике post938: w960/q75=146128B, w160/q75=7256B для56pxслота;
это пример лишних байтов, не обещание ускорения всех экранов. До переноса старых
клубных файлов нельзя повышать public TTL для всей папки feed. Точный исходный
замер и сохранение качества: [исследование экранов](../audits/post-video-screen-speed-2026-10-26.md).

## 11. Старые клубные источники: порядок совместного перехода

Backend-код переноса и inline JPEG/PNG/GIF уже выложен в5c0df13. Массовый перенос
388 привязок и закрытие прежних источников **не выполнялись**. Не показывать
заглушки вместо имеющихся файлов и не считать проблему выключенным флагом:
private content/media/video/library на сервере уже true.

Для возвращённых защищённых content/media URL использовать существующий
авторизованный загрузчик; не передавать их Next optimizer. Сохранить Range для
видео, inline MIME и анимацию GIF. Нового HTTP API для операторского переноса нет.

До отзыва старых публичных адресов расширить существующий `src/proxy.ts`:
серверный список точных S3-ключей, проверка перед выдачей кеша `/_next/image`,
включая явно кодированные старые варианты. Список из закрытого manifest
не публиковать в bundle/public/HTML/capabilities. Не запрещать весь бакет или
папку: две общие публичные обложки исключены, 49 посторонних ключей сохраняются.
Пока перенос/отзыв не согласованы и не проверены, guard остаётся выключенным.

Приёмка: до включения старые рабочие карточки прежние; после переноса private
байты доступны admin/member, недоступны guest/без подписки/после отзыва;
после отдельного закрытия старый прямой и закешированный optimizer URL отказаны,
а бесплатные материалы/публичные обложки открываются. Не ослаблять CSP/nonce,
API proxy или matcher ради этого изменения. Точные нормализация/конфликты/
восстановление описаны в [техническом приложении](frontend-legacy-media-retirement-2026-10-27.md);
данный документ — единая очередь задач фронтендеру.
