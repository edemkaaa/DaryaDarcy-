# Форматы статичных изображений фронтенда

Изображения в `apps/frontend/public/assets` приведены к WebP. Исключения —
`images/icon.png` и `images/favicon.png`: они используются для установки
приложения и значка браузера. Изображения из API и файлы на S3 не изменяются.

Обычные фотографии переводятся с качеством 85. PNG, прозрачная графика
и полноразмерные изображения с просмотром деталей кодируются без потерь.
Размеры сохраняются; при конвертации без потерь скрипт сравнивает отображаемые
RGBA-пиксели. Уже сжатые WebP повторно не сжимаются. Для превью фотографий
из JPEG разрешено заменить прежний lossless WebP более лёгким WebP.
Полноразмерная версия без потерь используется при увеличении; карточки
используют отдельные превью шириной до 1440 пикселей.

Обновление изображений из исходников:

```sh
node tooling/assets/prepare-frontend-image-variants.mjs --write
node tooling/assets/generate-frontend-image-catalog.mjs
```

Подготовка вариантов сохраняет нормализованные файлы и автоматически
приводит новые изображения к принятому формату. Для отдельной проверки
или очистки:

```sh
node tooling/assets/normalize-frontend-images.mjs
node tooling/assets/normalize-frontend-images.mjs --write
node tooling/assets/generate-frontend-image-catalog.mjs
```

Скрипт обновляет ссылки в исходниках и манифест, затем удаляет заменённые
файлы и изображения без ссылок. У вариантов в `assets/responsive` хеш
в имени всегда соответствует новым байтам, чтобы сохранялось корректное
неизменяемое кеширование.

В `image-variants.json` поля `origin`, `originalBytes`, `originalSha256`
описывают исторический источник. Поля `full`, `fullBytes`, `fullSha256`
описывают файл, который сейчас отдаёт приложение. Поэтому старое расширение
в `origin` не означает наличие лишнего файла в репозитории.
