## 1. «Сохранённое» — profile-screen.tsx

Вместо `feed.savedPosts.useQuery` использовать `feed.savedPostsPage`:

```ts
{ target: "feed", limit: 20, cursor: null }
// Следующая страница: тот же target/limit, cursor: previous.nextCursor.
// Вкладка Клуба: target: "club", новая первая страница.
```

Ответ `{items,nextCursor}`. `nextCursor` — строка или null, расшифровывать и
строить её на клиенте не нужно. По умолчанию20 элементов, максимум50;
некорректный лимит/курсор/контекст даёт400, а не молчаливую первую страницу.

Поля поста и медиа прежние. Порядок — самые новые сохранения сначала;
исторические дубли postId объединены. Сервер отбирает опубликованные доступные
посты до LIMIT. feed включает feed/both, club включает club/both; открытые both
не становятся платными. Для открытого «Сохранённого» достаточно входа.

Не получать все страницы заранее для локального разделения на две вкладки.
Ключ — аккаунт + target + limit; cursor — pageParam. Сохранить существующий
контроль доступа к удержанным данным при отзыве подписки и смене аккаунта.
Лайки/сохранение/отмена сохранения инвалидируют соответствующие новые ключи;
не считать отсутствие поста в первой странице доказательством отсутствия сохранения.

## 2. Участники — admin-screen.tsx

Вместо `admin.members` использовать `admin.membersPage({limit:20})` и
`items/nextCursor`. Не грузить участников при входе во вкладку оплат: она
отображает email/orderId самого платежа и не использует этот массив.

Порядок createdAt DESC/id DESC; прежние безопасные поля, включая
clubExpiresAt, blockedAt и blockedReason. Платежи агрегируются только для
аккаунтов страницы. Модератору административный список не открывается.

Для сверки конкретного действия:

```ts
admin.membersPage({ userId, limit: 1 });
// Без cursor: items содержит 0/1 аккаунт, nextCursor:null.
```

В read-after-write нельзя заменить полный список чтением произвольной первой
страницы и объявить действие подтверждённым. Проверять нужный userId и нужные
поля; `requireIdList(page)` заменить проверкой структуры page/items. Прежние
правила неопределённого исхода сохраняются: не повторять grantClub вслепую
при потерянном ответе, чтение срока не обеспечивает exactly-once выдачи.

## 3. Комментарии — club-comments.tsx / use-private-comment-files.ts

```ts
club.commentsPage({ postId, limit: 20 }); // корни
club.commentsPage({ postId, parentId, limit: 20 }); // прямые ответы
```

Ответ `{items,nextCursor,totalCount}`. У элемента прежние поля комментария,
автор/фото/реакции и новое `replyCount` — число прямых ответов. `totalCount` —
все комментарии поста, включая ответы; не заменять его длиной загруженного массива.
Каждая группа упорядочена createdAt ASC/id ASC, имеет отдельные страницы и ключ
аккаунт + postId + parentId/null + limit. Ответы на ответы поддерживаются тем же
методом, все дочерние ветки целиком сервер не присылает.

Не строить дерево из одной неполной плоской страницы и не выкачивать весь тред
автоматически. Догружать ответы видимых/открытых веток, ограничивая параллелизм.
Существующий компонент рекурсивно показывает вложенные ответы: эту возможность
не терять. Для родителя другого поста/отсутствующего родителя —404.

Чтение открытого опубликованного поста остаётся доступно обычному вошедшему
аккаунту; для club нужна подписка/staff. Гость —401, подтверждённый отказ в
клубном доступе —403. 503/сетевой сбой не выдавать за пустой подтверждённый тред.

В обоих путях отправки, включая журнал приватных фото, изменить cancel/query/
setData/invalidate и read-after-write с учётом группы. Возвращённый add/replay ID
не искать перебором страниц; не отправлять повторно лишь потому, что ID не виден
в первой странице. Ключ повторной отправки и журнал не менять. После удаления
родителя обновить корни и его группу: старый механизм переносит прямые ответы
в корень, а дальнейшую вложенность сохраняет.

## Общие правила догрузки

- Окончание только по nextCursor:null. Повтор того же cursor — остановка с
  ошибкой/повтором по действию, не бесконечный цикл.
- Не отправлять параллельно несколько догрузок одной группы; объединять ID,
  отменять запросы при выходе/смене владельца. Смена контекста сбрасывает цепочку.
- Не подключать минутный refetch всего infinite archive. Фоновая проверка
  первой страницы отдельно; при изменении последовательности ID заменить
  цепочку и сбросить старые курсоры. Если ID прежние — обновить поля первой
  страницы. Проверка прав и очистка закрытого кеша независимы от совпадения ID.
- `httpBatchLink` ограничить maxItems20, серверный предел не повышать.
- Существующие числовые курсоры feed/club/admin posts/VK не менять на строки:
  строки относятся только к трём новым методам.
